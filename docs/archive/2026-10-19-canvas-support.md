# Canvas 卡片适配（历史候选与验证记录）

当前交付状态：已通过 PR #32 合入 main，并随 0.9.0 发布；以下实测仍限于各自所列构建。

历史分支：`codex/canvas-support`，基于 `f952d96`。记录当时尚未合入 main 或公开发布。测试包沿用 0.8.2 版本号，不代表新的正式版本。

## 原因与实现

Canvas 文字卡片的 Markdown 编辑宿主没有 `file`，文件卡片也不是 MarkdownView 叶子。原选区菜单在文字卡片中因缺少文件直接返回，既有写回校验则会拒绝两类卡片。卡片预览使用独立的 Markdown 组件，原阅读视图只查找普通 Markdown 窗格，因此退出编辑后也不会显示布局。

`src/view/canvas.ts` 按实际卡片、子组件及编辑器解析来源：文字卡片以所在 Canvas 为资源路径，文件卡片以其 Markdown 文件为资源路径。写入仍只由 `writeBack.ts` 对发起卡片的 CodeMirror 缓冲提交一次事务，让宿主保存卡片文字或文件；绝不把 `.canvas` JSON 当 Markdown 交给文件改写。卡片已删除、替换、退出编辑、断开或 Canvas 只读时拒绝写入，原文断言和运行期块身份校验不变。

预览沿用共用阅读视图的布局绘制、正文匹配及段生命周期，以卡片子组件隔离快照。Canvas 会先准备预览、再结束编辑，因此独立预览宿主可以在隐藏期间接收段；准备期间没有可见尺寸不等于测量完成。文字卡片的未保存草稿按编辑缓冲隔离，不转移到同一 Canvas 文件里的另一个卡片或重建的缓冲。

图片右键菜单、输入保护的文档监听覆盖 Canvas iframe。CodeMirror 创建后可能才被宿主迁入 iframe，监听在节点挂载及编辑器更新时重新核对所属文档，每个文档只安装一次。

## PR #32 私密审查修复：复用段落后的快照同步

Canvas 删除第一行媒体时，宿主可以直接复用剩余段落，不再次调用后处理器。原 reader 因此停留在旧快照，剩余行继续使用旧行序号及设置。现在 Canvas reader 在唤醒、预览 DOM 变化和滚动时先核对卡片当前文本，再沿用共用快照与段落安装校验；普通 Markdown 来源规则不变。正文变化且布局未变时不额外整页重绘，移除最后一个布局也会释放 reader 和环绕状态。

- Node 24.11.1：`npm run check`（类型检查、lint、497 项测试）与 `npm run build` 通过；新增四项测试覆盖布局事件、DOM 变化、正文复用和最后一个布局移除。原实现下三项缺陷用例失败，修复后通过。
- Windows／Obsidian 1.14.4／默认主题／`vml-test-vault`：固定 PR 提交 `7178a9f` 的基线构建复现真实按键删除首行后，剩余媒体仍为第 2 行／300px，重绘 0 次；修复构建重新安装为第 1 行／100px，重绘 1 次。同一多图行在相同 Canvas 缩放下，实测屏幕高度由 166.23px 降为 55.41px，与设置比例相符，截图已检查。Ctrl+Z 一步恢复源缓冲原文。
- 修复生产脚本 SHA-256：`d4161bd43957bbbc364b30e68d1abe90be90cc7cb0bfee1aaccb6f8297d3cd39`。本次只验证卡片收到新文本后的预览更新；宿主向卡片同步源码的时机未改动，撤销检查不作为卡片预览自动同步验收。移动设备、其他主题和 Canvas 导出未复测。

## 范围

本次支持卡片内部布局的编辑与预览，不支持跨卡片拖放布局。全库批量移除仍只扫描 Markdown 文件，不遍历 Canvas 文字节点；交叉引用点击导航仍保留普通 Markdown 窗格的实现。本次未验证文件卡片的标题／块子路径、弹出窗口、移动设备、其他主题或 Canvas 导出。
