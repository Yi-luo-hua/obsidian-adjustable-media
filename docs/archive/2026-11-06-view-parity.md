# 保留原生编辑的视图间距对齐

用户要求实时预览与阅读视图切换后保持排版一致，随后明确选择：保留原生编辑体验，先消除能够修复的差异。此次不改为整段 HTML 替换式编辑，也不把有限样例的结果当作任意 Markdown 的一致性保证。

## 本次改动

- 实时预览中，一级标题后的空行使用与其他标题一致的段落间距。水平线和下一标题之间的空行也按段落间距处理。
- 折叠水平线的行框只保留边框高度；进入源码编辑时沿用宿主的正常行高。
- 标题内部 CodeMirror 的不可见光标缓冲图片保留原尺寸，改为顶端对齐，避免额外撑高行框。正文首个元素为标题时取消多余的顶部内边距。
- 阅读视图的普通段落和标题保留第二个起的连续空行，每行增加一个 `--p-spacing`，与实时预览已有规则一致。源码扫描跳过布局内部、代码围栏、公式、frontmatter 和注释；只改 DOM，不改笔记。
- 保留段落复用时，随来源快照更新间距并通知宿主重新测量；隐藏阅读 DOM 在模式切换时保留既有间距，避免下一次显示前先折叠再展开。无布局笔记不增加这些间距。

## 验证

2026-11-06，Windows／Obsidian 1.15.0（安装器 1.14.4）／默认主题／专用测试库 `vml-test-vault`。以 0.9.4 加本分支的生产构建验证。测试笔记包含 H1／H2／H3、普通正文、单图右环绕、水平线与下一节、三个连续空行，共 10 个唯一文字标记。

同一窗格分别在实时预览和阅读视图中滚到顶部，光标停在文末空行，测量文字 Range 的绝对坐标及相对首标题的坐标，不把可见源码标记算作阅读排版。对比结果：

| 范围 | 修复前 | 修复后 |
| --- | --- | --- |
| 一级标题后正文的相对位置差 | 8px | 小于 0.01px |
| 水平线后标题的累计相对位置差 | 约 40.6px | 726px 正文约 0.07px，430px 正文小于 0.01px |
| 三个空行后正文的累计相对位置差 | 约 72.6px | 726px 正文约 0.07px，430px 正文小于 0.01px |
| 全部 10 点的绝对文字位置差 | 首标题本身另有约 16px 偏移 | 两种宽度均不足 0.1px，横向不足 0.01px |

430px 使用测试标签页内的临时 CSS 固定两种视图的正文宽度，未修改库配置。两种宽度各连续切换四次，逐帧记录水平线及三个空行后正文的位置：有内容的可见帧坐标跨度均为 0，随后检查上下滚动。截图检查排版完整，无破图／覆盖／错误界面。

通过 Electron DevTools 协议发送真实鼠标点击与输入：二级标题在预期行插入“验证”，Ctrl+Z 一步还原；光标进入水平线后恢复约 24px 的正常编辑行高。临时笔记还原后核对 SHA-256，再回收；恢复测试库原插件与样式，关闭临时标签页。

`npm run check` 通过：类型检查、lint（已有警告，无错误）、563 项测试；`npm run build` 通过。新回归用例覆盖 H1／水平线边界、额外空行、受保护内容和阅读保留段复用。宿主无捕获错误。

## 范围

本次尚未统一无空行标题前的所有间距、列表／引用后连续空行、英文行尾空格的换行行为、原生代码／公式／表格编辑状态、frontmatter 后首标题及所有主题的自定义样式。光标进入 Markdown 后显示源码，尺寸可能随原生编辑状态变化。

未复测移动真机、macOS、其他主题或完整 PDF。PDF 沿用原生多空行折叠行为。这些边界不记作通过；本次结果仅表示所列样例已达到亚像素对齐，尚未发布新版本。
