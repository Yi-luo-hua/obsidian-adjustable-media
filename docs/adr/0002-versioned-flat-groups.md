# 用版本化平坦成员保护新的跨块关系

当前解析器保留 V2 未知字段并允许编辑，因此在 V2 上增加组字段不能保护旧版本不理解的组关系。推荐候选是在每个参与组的原有块注释中使用新版本、成员 ID、groupId 与单一 owner 组设置；只转换明确操作的目标块，保留每个成员的内容范围。

0.6.1 基线解析器对 v:3 拒绝普通模型编辑，但二次核验确认基线移除注释命令与批处理仍能破坏未知版本；版本号不是完整隔离。当前开发分支已增加统一写入保护，并通过定向命令、事务及撤销验证，见 [08 记录](../plans/layout-redesign/08-pane-foundation-record.md)；这不替代 P4 的代表性旧构建及完整入口矩阵。外层 wrapper 包内部 V2 也允许内部编辑，且增加嵌套语法。首选候选以 R1 先补齐未知版本入口保护、R2 仅支持经验证的保护构建降级为前提；0.6.1 基线及更早构建不承诺只读安全。若必须包含这些旧构建，需另选策略。

平坦候选的代价是旧版失去组样式。新插件必须校验连续成员、唯一 ID、owner 和顺序，适配所有内部编辑与成员消失操作；破损关系不自动修复文件。

接受条件：P4 在代表性旧发布构建、无插件及当前解析路径中验证全部读写入口，证明目标范围原文守恒和一次事务恢复。字段及版本号在该门槛通过后冻结，不在本 ADR 提前宣布 V3 已成为规范。

依据：[格式研判](../plans/layout-redesign/04-groups-and-format.md)、[补充研究](../research/LAYOUT_CONFLICTS.md#7-实施规划前的补充研判)。
