# 设计说明

本文说明 Adjustable Media 的存储格式、代码结构和写入规则，以及开发时在 Obsidian 里实测确认过的行为。

## 1. 存储格式

### 1.1 语法

```markdown
<!-- vml {"v":2,"rows":[{"height":240,"widths":[1,1.4],"captions":[null,"草图"]},{"width":0.6,"align":"center"}]} -->
![[beach.png]] ![草图](attachments/sketch.png)
![[clip.mp4]]
<!-- /vml -->
```

- **开始注释**：整行为 `<!-- vml {JSON} -->`，顶格书写；没有任何设置时写成 `<!-- vml -->`，只有块级设置、没有行设置时省略 `rows`（各版本都把缺少的 `rows` 读作没有行设置）。
- **结束注释**：整行为 `<!-- /vml -->`，顶格书写。
- **一行就是一行布局**：两条注释之间只有图片或视频嵌入（`![[…]]` 或 `![…](…)`）的非空行是一行布局，嵌入之间可以有空格，也可以紧挨着。空行会被忽略。
- **文字栏**：块内其他的行都是文字，按普通 Markdown 显示在图片旁边。第一行图片之前的文字排在左边一栏，最后一行图片之后的文字排在右边一栏，图片那一栏夹在中间，相当于 LaTeX 里并排的几个 minipage。嵌入的不是 Obsidian 支持的媒体格式（例如嵌入一篇笔记），或者嵌入后面还有别的文字，这一行也算文字。

  ```markdown
  <!-- vml {"v":2,"width":0.4} -->
  左边一栏，可以写多行、多段，
  也可以有标题、列表和引用。
  ![[beach.png]]
  右边一栏。
  <!-- /vml -->
  ```

- 文字写在两行图片之间，或者块里只有文字、没有图片，这个块就判为无效：插件不接管，交给 Obsidian 按普通 Markdown 显示。
- 围栏代码（`` ``` ``、`~~~`，包括写在列表标记后面的）、frontmatter、`$$` 公式和注释（`%%`、多行 HTML 注释）里的内容一律不识别。
- 插件写入时一行最多 4 个嵌入；手写超过 4 个时按 4 个一行折行显示，但不改动文件。
- 写入 JSON 时，`--` 转义成 `-\u002d`（避免提前闭合注释），`%` 转义成 `\u0025`（避免奇数个 `%%` 让整行被当成 Obsidian 注释）。`JSON.parse` 能正常读回。

### 1.2 元数据字段

`rows[i]` 对应块内第 i 行图片，文字行不算在内。

| 字段 | 适用 | 含义 | 默认值 / 范围 |
| --- | --- | --- | --- |
| `v` | 块 | 格式版本 | `2` |
| `width` | 块 | 整个布局块占容器宽度的比例；有文字栏时是图片那一栏的宽度，文字栏分掉剩下的 | 占满；0.2～1，占满时不写。环绕或有文字栏时不写即为 0.4，最宽 0.8 |
| `wrap` | 块 | 文字环绕：布局块浮到 `left` 或 `right` 一侧，笔记自己的正文从旁边绕过，超出图片高度后恢复整行宽度 | 不环绕 |
| `skip` | 块 | 环绕的布局块从所在位置往下错开几行才开始，上面这几行保持整行宽度 | 0；1～40，没有 `wrap` 时不写 |
| `valign` | 块 | 文字栏和图片在竖直方向上怎样对齐：`center` 居中，`bottom` 靠下 | 靠上；没有文字栏时不写 |
| `height` | 行 | 行高（px） | 220；80～900 |
| `widths` | 多图行 | 各列宽度比例，按嵌入顺序 | 按媒体宽高比分配 |
| `width` | 单图行 | 占所在行宽度的比例 | 嵌入里写的尺寸，否则原图大小；0.1～1 |
| `align` | 单图行 | `left` / `center` / `right` | `center` |
| `offset` | 单图行 | 自由水平位置：图片左边的空白占整行空白的比例，0 靠左、1 靠右；有它时忽略 `align` | 0～1 |
| `captions` | 行 | 各项图注，`null` 表示没有 | 无 |
| `captionAlign` | 行 | `left` / `center` | `left` |

只写用户实际设置过的字段，尽量让开始注释短。不认识的字段写回时原样保留。数值保留 3 位小数。

单图的水平位置正好是靠左、居中、靠右时写成 `align`，旧版本插件也能读懂；停在其他位置才写 `offset`。旧版本不认识 `offset` 和块级 `width`，会按居中、占满显示，写回时原样保留它们。

环绕的布局块紧贴在被环绕的正文上方书写（结束注释下一行就是正文），和 LaTeX 的 `wrapfigure` 一样：块在笔记里的位置决定图片从哪里开始，`skip` 再往下错开几行。旧版本不认识 `wrap` 和 `skip`，会按不环绕显示，写回时原样保留。没有插件时，图片显示在那段正文上方。

有文字栏的块不浮动：它的 `wrap` 和 `skip` 留在注释里、写回时原样保留，但不起作用；菜单里不提供环绕选项，整块移动时也只能放在段落之间。旧版本插件把有文字栏的块判为无效，交给 Obsidian 按普通 Markdown 显示，不会改写它。没有插件时，文字和图片按书写顺序上下排列。

### 1.3 容错规则

| 情况 | 处理 |
| --- | --- |
| JSON 解析失败，或 `v` 不是 2 | 按默认值显示并提示；**这个块不可编辑**，插件不会改写它 |
| 文字写在两行图片之间，或者块里只有文字 | 这个块无效，交给 Obsidian 按普通 Markdown 显示，插件不改写它 |
| `rows` 比实际行数少 | 多出的行用默认值 |
| `rows` 比实际行数多 | 忽略多出的部分；下次写回时去掉 |
| `widths` / `captions` 的长度和该行嵌入数不一致 | 这个字段对这一行无效 |
| 用户手工调整了嵌入顺序 | 设置按位置对应，可能错位，重新设置即可 |
| 文件被重命名 | Obsidian 更新嵌入文本，嵌入数量不变，设置仍然对得上 |

## 2. 代码结构

| 模块 | 职责 |
| --- | --- |
| `src/markdown/lineContext.ts` | 单遍扫描，判断每一行是正文、代码、frontmatter、公式还是注释 |
| `src/markdown/columnStyle.ts` | 文字栏编辑器怎样照实时预览画 Markdown：每个记号带哪些样式类，哪些标记在光标不在时隐藏，列表符号、任务方框、引用和链接的画法 |
| `src/markdown/columnEditing.ts` | 文字栏编辑器的按键：Tab 整行缩进的列表行，回车接续列表和引用，Ctrl+B、Ctrl+I、Ctrl+K |
| `src/format/v2.ts` | 识别布局块、解析嵌入（保留原文和列位置）和图片两侧的文字、读写元数据 |
| `src/layout/model.ts` | 布局模型和操作：移动、插入、移除、行高、列宽、单图宽度与位置、块宽度、整体缩放、图注、文字环绕与错开行数、文字栏的竖直对齐 |
| `src/layout/drawn.ts` | 阅读视图里画出来的布局依据了笔记的哪些内容，笔记变化后是否需要整体重绘 |
| `src/layout/edits.ts` | 把模型变化规划成行级修改（文字栏原样保留），添加文字栏时的空行，并在写入前定位、核对 |
| `src/layout/placement.ts` | 整块移动：块可以落在哪些位置，以及移动时的修改规划 |
| `src/layout/plainEmbed.ts` | 从块外的普通媒体行里取出一个嵌入，供拖进布局块 |
| `src/layout/writeBack.ts` | 唯一的写入入口 |
| `src/layout/geometry.ts` | 拖拽落点、列宽计算、单图水平位置与吸附、整块移动时的环绕方向和错开行数 |
| `src/layout/wrapGaps.ts` | 实时预览里环绕排版的几何规划：被推到浮动下方的元素前的占位，以及锚点不在渲染范围时的替身浮动 |
| `src/view/` | 布局渲染（阅读视图和实时预览共用，文字栏由 Obsidian 的 `MarkdownRenderer` 渲染）、实时预览里文字栏的直接编辑（`textEditing.ts`，编辑器本身在 `columnEditor.ts`）、实时预览里的交互（拖动、调整大小、范围框、整块移动；阅读视图只显示布局）、实时预览和阅读视图里环绕排版的维护（`wrapGuard.ts`、`readingWrap.ts`）、块外图片拖入、图片右键菜单、看图、弹窗、界面文字 |
| `src/input/` | 拖入 / 粘贴后的自动转换 |
| `src/commands/` | 命令 |

数据流：笔记文本 → `lineContext` → `v2` 解析出块 → `model` → 视图渲染；用户操作 → `model` 的操作函数得到新模型 → `edits` 规划修改 → `writeBack` 写入 → Obsidian 重新渲染。

`src/view/`、`src/input/autoConvert.ts`、`src/commands/register.ts` 依赖 Obsidian 接口；其余模块都是纯函数，由 `tests/` 里的测试覆盖。

## 3. 写入规则

1. 永远不改写嵌入文本和文字栏里的文字，只改开始注释，或者把嵌入整段搬走。
2. 每次修改都锚定在块渲染时的完整原文上。写入前，原文必须仍在原来的行上；如果笔记上方有改动导致块整体下移，就在正文里查找这段原文，**恰好出现一次**才写入（代码块里的副本不算）。找不到、不止一处、或同一次操作里两个修改指向同一个块，都放弃写入并提示。
3. 只改设置时只重写开始注释这一行，块内原有的空格、空行保持不变；嵌入的分布变了才重写整块。有文字栏的块重写时，第一行图片之前和最后一行图片之后的内容（文字连同其中的空行）逐字保留，只换掉中间的图片行。块里最后一个嵌入被移走时，只去掉注释和图片，左右两栏的文字作为普通段落留在原处，中间隔一个空行。删除整块时只顺带去掉周围多出的一个空行。块以外的内容一律不碰，CRLF 文件保持原有换行符。
4. 笔记在某个窗格里处于源码或实时预览模式时，通过那个编辑器的一次事务写入（可以撤销，不会丢掉没保存的输入）；否则用 `vault.process` 直接改文件。
5. 渲染时从不写文件。
6. 把块外的图片拖进布局块时，两处修改在同一次写入里完成：从原来那行取走嵌入（这一行只剩空白就整行删除，并顺带去掉周围多出的一个空行；否则只去掉嵌入和它后面的空格），再写进目标块。原来那行同样以原文锚定、核对，两处有一处对不上就都不写。只有整行都是媒体嵌入、位于正文、不在任何布局块里的行才能取出嵌入。
7. 整块移动布局块时，同样是一次写入里的两处修改：块从原处整段移走（两侧都是空行时顺带去掉一个，位于笔记开头时去掉后面的空行），再原样插到目标行前面，只有开始注释可能因为环绕方向、错开行数改变而重写。目标行连同它上面一行一起作为锚点核对。块只能落在顶层 Markdown 块的开头（空行、标题、另一个布局块或代码、公式、注释、frontmatter 结束之后的正文行）或笔记末尾，不会插进列表、缩进内容、代码、公式、注释和其他布局块中间。插入时块前面补一个空行；不环绕的块后面也补一个空行，环绕的块紧贴在它环绕的正文上方。目标就是原位时只改开始注释。
8. 在布局里直接编辑文字栏时，插件把文字栏编辑器里的文字写回这一栏自己的行：从这一栏的第一行到最后一行；这一侧还没有文字时，左栏插在开始注释后面，右栏插在结束注释前面；编辑器清空时去掉这些行。首尾的空行不写。每次写入同样锚定块的原文、核对后才写，而且写之前先检查：写入后这个块必须还能读回原来的开始注释、图片行和另一侧的文字，这一侧读回的正好是输入的文字。输入了只有图片的一行、代码围栏、`%%` 或布局注释这类会改变块结构的内容时不写入，编辑器的框标红并提示。
9. 有文字栏的块不参与合并：「与下一个布局块合并」命令拒绝合并，拖入、粘贴的新图片也不并入它，而是自成一个块。否则一个块的文字会落到另一个块的两行图片之间，块就无效了。

## 4. 实测确认过的 Obsidian 行为

开发时在测试库（Obsidian 1.13.7）里验证过，设计依赖这些结论：

- **阅读视图的分段**：开始注释、嵌入行、结束注释各是一个独立的段（开始注释下一行不需要空行，结束注释会截断段落），`getSectionInfo` 给出的行号准确。被嵌入到其他笔记里的内容没有段信息，保持 Obsidian 自己的渲染。
- **阅读视图只重绘变了的段**：文字没变的段会沿用旧的渲染结果。只改设置时，变的只有开始注释那一段，嵌入所在的段不会重新经过插件，于是继续显示旧布局，而且下一次修改会因为锚定的原文对不上而失败。插件因此在 `metadataCache` 的 `changed` 事件里比较这篇笔记的布局块注释行（有文字栏的块比较它的全部行，见 4.2），有变化就对显示这篇笔记的阅读视图调用 `previewMode.rerender(true)`（实测：`changed` 触发时视图已拿到新内容，`rerender(true)` 后显示正确）。
- **实时预览**：`StateField` 提供的块级替换装饰（`Prec.high`）能盖住 Obsidian 自己的图片嵌入组件；选区碰到块时取消替换即可显示源码。
- **阅读视图下不能写编辑器**：阅读模式的视图仍然有编辑器对象，但写它只会改到隐藏的内容，既不存盘也不刷新，切到别的笔记时修改会被丢弃。所以阅读模式下改用 `vault.process`。
- **注释的可见性**：不装插件时，阅读视图不显示 `<!-- -->` 注释，实时预览显示成灰字。同一行的大图在没有插件时会上下排列。
- **重命名**：重命名块内的图片后，Obsidian 会更新嵌入文本，Markdown 链接会按「最短路径」改写，块结构不受影响。
- **拖入 / 粘贴附件**：Obsidian 依次触发 `editor-drop` / `editor-paste`（带文件名），把附件存进库里，再用一个**没有 `userEvent`** 的事务插入 `![[文件名]]`，全程几十毫秒。一次拖入多个文件时，每个文件单独一个事务，除最后一个外都带一个空行。事件里的光标位置不可靠。自动转换因此按「记下预期数量 → 收集随后没有 `userEvent` 的嵌入插入」来实现。预期数量取自编辑器上的 DOM `drop` / `paste` 事件（CM6 `domEventHandlers`，最高优先级，只读取文件列表，不处理也不拦截事件），而不是 `editor-drop` / `editor-paste`：官方审核规则要求这两个事件的处理函数调用 `preventDefault()`，而那样会让 Obsidian 不再插入附件。
- **从 Obsidian 文件列表拖入**：`drop` 事件的 `dataTransfer` 里没有文件，Obsidian 用一个没有 `userEvent` 的事务直接插入 `![[文件名]]`。所以没有文件的 `drop` 也会开一个 2 秒的短窗口，数量未知，最后一次插入之后稍等再转换；拖入的是笔记或文字时插入的不是媒体嵌入，窗口到期作废。
- **文件右键菜单**：对媒体文件触发 `workspace.trigger("file-menu", menu, file, "link-context-menu")`，Obsidian 会加上「在文件列表中显示当前文件」「在系统资源管理器中显示」「在新窗口中打开」「复制路径」等项（1.13.7 实测），不需要调用文件列表的内部方法。
- **发布到 Hexo**：`marked` 会把 `<!-- vml … -->` 原样输出为 HTML 注释，页面上不可见。
- **实时预览里的普通图片**（1.13.7 实测）：单击图片会选中它（容器加上 `is-selected`），并把光标放到嵌入开头；再单击一次打开 Obsidian 自带的看图灯箱。「包成布局块」命令因此可以直接作用于刚点过的图片，用户给命令绑个快捷键即可（插件不设默认快捷键）。图片还带有 Obsidian 自己的缩放角和右键菜单；桌面端 `img` 默认可以被浏览器原生拖动。
- **图片右键菜单**：Obsidian 为实时预览里的图片弹出自己的菜单时，会在 `contextmenu` 事件里同步触发 `file-menu`（来源 `link-context-menu`），但不带被点的是哪一个嵌入。插件在捕获阶段记下 `contextmenu` 的目标元素，在 `file-menu` 里用 `EditorView.findFromDOM` 和 `posAtDOM` 找回它所在的行，再加上「包成布局块」。
- **块外图片的拖动**：插件直接在编辑器的 DOM 上监听 `pointerdown`，不依赖 CodeMirror 是否把图片部件里的事件交给扩展；指针移动超过阈值才接管，所以 Obsidian 的单击选中、缩放角和菜单不受影响。插件跟随拖动期间，浏览器原生的图片拖动必须取消，否则它会接管手势，并在松手处插入图片地址。取消要在捕获阶段、在编辑器的 `contentDOM` 上完成（`preventDefault` 加 `stopPropagation`）：Obsidian 的拖动管理器（`dragManager.handleDrag`）把 `dragstart` 监听直接挂在图片元素上，一收到就给 `body` 加上 `is-grabbing`（全局 `cursor: grabbing !important`）并记下 `dragManager.draggable`，两者都只在原生 `dragend` 时撤销。如果在冒泡阶段才取消，拖动已经由 Obsidian 开始，却永远等不到 `dragend`，指针会一直停在抓握状态（1.13.7 实测）。插件没在跟随拖动时不拦截，Obsidian 自己的图片拖动照常工作。拖动结束后浏览器仍会在松手处补发一次 `click`，插件把这次点击吞掉，免得实时预览选中松手处的图片。
- **阅读视图的灯箱**：阅读视图对段落里任何没被 `preventDefault` 的 `img` 单击都会打开灯箱，插件画的布局图片也一样，所以阅读视图不另做看图。实时预览的灯箱只认 Obsidian 自己的图片部件，插件调用不到，因此自带一个看图弹窗（双击打开）。全屏的 `Modal` 在 1.13.7 里没有自带的关闭按钮，看图弹窗自己画一个。
- **阅读视图只显示布局**：拖动、调整大小、右键菜单和文字栏的直接编辑都只在实时预览里，阅读视图里的布局不挂任何交互。实测（1.13.7，用 DevTools 协议发送真实的点击和拖动）：`text-test.md` 的四个布局都没有手柄，右键不弹任何菜单（Obsidian 在阅读视图里也不给这些图片弹菜单），拖动图片什么也不跟随，单击文字栏不进入编辑，单击图片照常打开 Obsidian 的灯箱（`lightbox`，和普通嵌入的图片一样）。

### 4.1 文字环绕

环绕用 CSS 浮动实现：布局块浮到一侧，笔记自己的段落从旁边绕过。以下都在测试库（1.13.7）里逐项测过，缺一项都会出错。

- **阅读视图**：浮动会自己溢出所在的段，后面各段的文字直接绕排，不需要额外处理。代码块和表格本身就是独立的格式化上下文，会自动缩窄排在图片旁边。引用块的竖线、Callout 的底色、分隔线和行间公式会被压在图片下面，嵌套列表会丢掉缩进，所以笔记里有环绕的块时，这几种元素改成 `display: flow-root`，作为一个整体排在图片旁边。Obsidian 的标题不清除浮动。
- **实时预览的锚点**：CodeMirror 把各行和各部件的高度逐个加起来，得到每个元素的位置（高度表），点击定位、方向键和虚拟渲染都依赖它。环绕的块的部件高度为 0，只作为锚点，布局块从里面浮出去。旁边的行按各自的实际高度测量，高度表因此保持准确。实测：行位置零偏差，旁边文字的点击定位、上下方向键、在旁边打字时的实时重排都正确。
- **实时预览里要改掉的四处 Obsidian 样式**：
  1. Obsidian 给所有块级部件设了 `contain: paint !important`（`.cm-content > [contenteditable=false]`），浮动会被关在部件里。环绕的块用选择器更具体的规则取消。
  2. 编辑器的行是 `position: relative`，定位元素绘制和接收点击的层级都在浮动之上，点图片会点到文字。浮动设 `z-index: 1`。
  3. 标题、代码块、分隔线和脚注的行带 `clear: left`，会被推到图片下面，推开的空隙不属于任何元素，高度表从这里开始整体偏移（实测 77px）。笔记里有环绕的块时，行不再清除浮动，标题也照常绕排。
  4. 列表、引用的悬挂缩进是 Obsidian 渲染时实测出来、写在行内样式里的。在图片旁边量，会把图片宽度也算进去（实测 327px），列表第一行滑到图片底下。这些行改成 `display: flow-root`，作为一个整体排在图片旁边，从自己的边缘量。
- **外边距**：CodeMirror 只量元素的盒子，不算外边距。去掉 `contain` 后，布局块自己的外边距会穿出部件，后面每一行都偏移 12px，所以实时预览里布局块的上下间距改用部件的内边距。不环绕的布局块要排到浮动下方，它的清除间距也留在部件内部，由 CodeMirror 量到。
- **放不到图片旁边的元素**：宽度不够、只能排到浮动下方的部件，推开的空隙同样不属于任何元素。`wrapGuard.ts` 在每次测量后比较各元素的实际位置和高度表，发现这种空隙就在该元素前插一个同样高的占位部件，浮动变化时占位跟着变高、变矮或移除。块级部件只能由状态字段提供，所以占位通过状态效果写入。实测里 Obsidian 的表格和 Callout 都能缩窄排在旁边，这个机制作为兜底。
- **很高的浮动**：CodeMirror 只渲染视口附近的内容；跳转时只往目标上方多渲染约 500px。浮动的锚点不在渲染范围、浮动却伸进来时，旁边的行会失去绕排，等锚点渲染出来再跳回去。`wrapGuard.ts` 记住每个浮动的尺寸，这时在第一条渲染出来的行上放一个同样大小、只显示下半截的替身浮动。实测：跳到 605px 高的浮动下半截旁边再往上滚 800px，文字零跳动，替身和真浮动交接时也不动。
- **显示源码时**：块显示源码后，Obsidian 会把块里的嵌入按原尺寸渲染成图片（实测一张竖图 1244px 高），整篇笔记跟着大幅移动。所以块的每一行带上 `vml-source-line`，其中的图片、视频缩成缩略图；环绕的块还在第一行开头放一个只读的浮动，源码行排在它旁边，后面的文字继续绕排。实测显示源码时正文只下移约 120px，且保持绕排。
- **错开行数**：`skip` 用一个宽度为 0 的浮动把布局块往下垫，高度按 `lh` 单位（行高）计算，被垫过的行保持整行宽度。
- **多个浮动**：左右各一个浮动时，正文从两者中间穿过；一个高浮动旁边再开始一个另一侧的浮动，或者同一侧上下两个浮动（后一个排在前一个下方），都照常绕排。上面的机制按浮动逐个处理，不需要额外的规则。实测（测试库的 `wrap-multi.md`）：实时预览来回滚动三轮，高度表零偏差，跳到两个高浮动的下半截时两个替身同时生效；阅读视图以 40px 步长来回滚动三轮，没有文字失去绕排，也没有跳动。
- **阅读视图的虚拟渲染**：阅读视图也只把视口附近的段留在页面里（`updateVirtualDisplay`），每段的高度记为到下一段顶端的距离（`measureSection`）。环绕的布局块所在的段因此是 0 高，渲染范围的上边界一越过它的顶端它就被收起，而旁边的文字因为自己有高度还留着，于是失去绕排，下面的内容整体移动（实测：紧跟一个不环绕的块时移动 198px，正是清除浮动的距离）。`readingWrap.ts` 在布局块那段还在页面里时，给浮动旁边的每一段预先放一个隐藏的替身（与实时预览的替身同一套尺寸规划），标出布局块那段和这些段。CSS 只让"前面既没有布局块那段、也没有另一个带替身的段"的那个段显示替身，也就是第一个还留在页面里的段。Obsidian 收起布局块那段的同一刻，替身就生效了，它随后测量各段时量到的仍是绕排后的高度。替身必须事先放好：`updateVirtualDisplay` 在同一个同步调用里收起段并立即测量，`MutationObserver` 的回调来不及（实测：来不及时下一次收起这些段会再跳 234px）。替身的外层用 `display: contents`，不改变外边距的折叠。Obsidian 按记录的高度算位置，布局块那段本来就记为 0，替身不影响它的计算。剩下的限制：新打开的笔记从下往上第一次滚进一个从没显示过的环绕区域时，布局块那段还没进过页面、量不到，这一次仍会跳动。

### 4.2 文字栏

以下同样在测试库（1.13.7）里测过。

- **渲染**：文字栏由 Obsidian 的 `MarkdownRenderer.render` 渲染，标题、列表、引用、链接和嵌入都和正文显示得一样。渲染结果挂在一个 `Component` 上：实时预览里是部件自己的，部件销毁时一起卸载；阅读视图里是这一段的 `MarkdownRenderChild`。
- **实时预览里的空白**：编辑器内容区是 `white-space: pre-wrap`，Obsidian 渲染结果里元素之间的换行会显示成空行（实测一栏有标题、段落和列表时高出 65px，列表项之间也被拉开）。文字栏改成 `white-space: normal`。
- **实时预览里的链接**：文字栏里的链接由 Obsidian 自己处理：单击在当前标签页打开，Ctrl+单击打开一个新标签页，悬停显示页面预览。插件如果也处理，会打开两个标签页，所以插件不处理链接。
- **在布局里直接编辑**（实时预览，`textEditing.ts`、`columnEditor.ts`）：点文字栏时，只有这一栏换成一个编辑器，显示这一栏的源码，布局其余部分不动；拖选文字复制时不切换。插件写不进的块（设置读不懂）点文字仍然显示整块源码。
  - 编辑器是嵌在布局部件里的另一个 CodeMirror 编辑器。笔记的编辑器不管部件里的 DOM 变化和事件：`WidgetView` 和 `BlockWidgetView` 的 `ignoreMutation` 恒为 true，`ignoreEvent` 交给部件（布局部件恒为 true）；焦点在里面的编辑器上时，它也不读选区（`onSelectionChange` 只认自己的 `contentDOM`）。两个编辑器因此互不干扰。
  - 样式和笔记的编辑器一样。Obsidian 的 Markdown 语言可以用 `@codemirror/language` 公开的 `language` facet 从笔记编辑器的状态里取到（一个名为 `hypermd` 的 `StreamLanguage`），装进另一个 `EditorState` 后，解析结果和笔记编辑器逐个记号相同。每个记号的名字是它的各个样式用 `_` 连起来，笔记的编辑器给记号的文字加上「`cm-` 加样式名」的类，给所在的行加上以 `HyperMD-` 开头的样式名：`formatting_formatting-strong_strong` 画成 `cm-formatting cm-formatting-strong cm-strong`，`HyperMD-header_HyperMD-header-1` 是行上的 `HyperMD-header HyperMD-header-1`。编辑器按同样的规则加类，又位于笔记编辑器的 DOM 里，Obsidian 和主题写给笔记编辑器的 CSS 就原样作用在上面，标题字号、粗体、链接颜色、列表标记都和笔记里一样。实测：标题、粗体、斜体、删除线、高亮、行内代码、链接、内部链接、标签、公式、列表、任务、引用和 HTML 的记号名与类名全部对得上。取不到这个语言时（例如以后 Obsidian 换了实现），编辑器照样能输入，只是没有样式。
  - 标记按实时预览的画法处理（`columnStyle.ts`）。实测实时预览（1.13.7）：标题和引用的标记在光标所在的行上才显示；粗体、斜体、删除线、高亮、行内代码和链接的标记要等光标碰到这一段才显示，同一行的其他地方不算；不显示时这些标记画成空白，链接只剩文字（外面套一层 `cm-underline`）；引用的 `>` 变成透明（`cm-transparent`），竖线由行的 `::before` 画出，第二层起的 `>` 是 `cm-blockquote-border`；列表符号不论光标在哪都画成圆点或编号（`-` 外面套 `list-bullet`，`1. ` 外面套 `list-number`，样式来自 Obsidian 的 CSS）；任务的 `- [ ]` 换成一个复选框（`task-list-label` 里的 `task-list-item-checkbox`）；嵌入画成图片。编辑器照这些规则加类或隐藏，只有嵌入保留源码（编辑器里不画图片）；点复选框就在文字里改写 `[ ]` 或 `[x]`，焦点和光标都不动。
  - 编辑器在笔记编辑器里，可读行宽的规则也作用在它上面（`max-width: 700px`），但文字栏总比笔记窄，这个限制不起作用。它的首行和画出来的文字栏一样没有上边距，其他标题行保留 Obsidian 给的上边距。实时预览里空行和别的行一样高（24px）；编辑器里光标不在的空行只有段落间距那么高（`--p-spacing`，16px），和画出来的文字栏一致。实测：进入编辑时文字的位置偏移不到 0.5px，这一栏的高度几乎不变：`text-test.md` 的 A 栏画出来 160px、编辑时 159px，B 栏 64px 和 63px（空行按整行算时 A 栏是 199px）。
  - 按键（`columnEditing.ts`）：Tab 在列表项上或选中了文字时整行缩进，其他地方在光标处插入缩进，Shift+Tab 减少缩进，缩进单位和制表符宽度取自笔记的编辑器；Tab 不再把焦点移出编辑器，用 Esc 退出。回车在列表项和引用行上接着写下一项：同样的符号、下一个编号、未勾选的方框；在空的项上回车时，缩进的项上移一级，不缩进的结束列表，空的引用行去掉一层 `>`。Ctrl+B、Ctrl+I 给选中的文字加上或去掉 `**`、`*`；没有选中时，去掉光标所在那一段的标记，或者放进一对空标记，再按一次又拿掉。哪两个标记是一对由语法树决定，所以在粗体里按 Ctrl+I 不会把粗体的星号当成斜体的。Ctrl+K 把选中的文字变成 Markdown 链接，光标停在填地址的括号里。这三个用的是 Obsidian 的默认键：Obsidian 的快捷键到不了这个编辑器（见下面的 `Scope`），改过的快捷键在这里不起作用。编辑器有自己的撤销记录，Ctrl+Z 撤销编辑器里的改动，笔记跟着变；按 CodeMirror 的规则，紧接在 Tab 后的 Shift+Tab 和它合成一步撤销。CodeMirror 默认键位里的切换注释（会改变块的结构）不启用，Ctrl+I 也不再是「选中上层语法」。
  - 编辑器里的每次改动立刻通过笔记的编辑器写回笔记（写入规则见第 3 节第 8 条），所以笔记自己的撤销记录也能撤销，连续的输入合成一步。
  - 笔记一变，CodeMirror 就会重建块部件，编辑器会跟着消失。输入期间部件用 `updateDOM` 保留原来的元素，条件是这次变化正好是输入的文字：开始注释、图片行和另一栏都没变。别处改动了这个块时，编辑器放弃，部件照常重建。
  - 输入法组字期间不写入：编辑器的 `composing` 或 `compositionStarted` 为真时先不写，组字结束后的下一次更新再写，`compositionend` 之后再补一次。桌面端的 CodeMirror 不用 EditContext（只在 Android 上用），组字事件照常发在编辑器的 `contentDOM` 上。
  - 输入期间插件压入一个没有父级的 `Scope`，Obsidian 的快捷键都不起作用，否则 Ctrl+B 这类编辑器命令会改到笔记的编辑器上；Esc 退出（组字时的 Esc 留给输入法取消组字）。焦点离开编辑器、落到页面的别处时（按 Esc、点笔记的其他地方），布局按笔记的内容重新画一遍。窗口失去焦点时 `document.activeElement` 不变，编辑器保持打开，切回来接着输入。
  - 从图片菜单「在左侧/右侧添加文字」打开编辑器时，推迟到菜单关闭之后的下一个任务。Obsidian 的菜单（子菜单也一样）显示后要到下一个任务才压入自己的按键范围（`setTimeout(load, 0)`），隐藏时只弹出已经压入的范围。编辑器如果在这之前压入了自己的范围，菜单的范围随后会叠在上面，回车被它吃掉。实测：指针停在带子菜单的「复制路径」上时点菜单项，三次都出现这种情况；推迟之后三次都正常。
  - 点击时光标放在点到的地方：取点击处之前渲染出来的几个字，在源码里恰好找到一处，就放在它后面，否则放在末尾（用 `caretPositionFromPoint`，Chromium 128 起才有）。
  - 实测（用 DevTools 协议发送真实的点击、文字、输入法组字和按键）：光标落在点到的字后面；A 栏的标题按标题字号显示、`###` 隐藏，内部链接只剩「内部链接」几个字，列表画成圆点；光标移到粗体那一行时 `**` 仍然隐藏，点到粗体上才出现；B 栏的引用有竖线、`>` 透明；输入、换行、Tab、Shift+Tab 都即时写回，撤销在编辑器里生效、笔记跟着变；在列表项后回车接出新的项，在任务后接出 `- [ ] `，空项上再回车结束列表；点复选框写成 `[x]`，焦点和光标不动；Ctrl+B 加粗、再按取消，Ctrl+I 斜体，Ctrl+K 得到 `[二]()` 且光标在括号里；Ctrl+E（Obsidian 切换阅读视图的快捷键）不起作用；组字期间笔记不变，确定后写回；写成代码围栏时框变红、笔记不变，删掉后恢复；Esc 和点击别处都会退出，重画后标题、粗体、列表、复选框都在；「在右侧添加文字」先只显示空编辑器，输入后才写入，回车正常；窗口最小化时编辑器收到 `blur`，但仍是 `activeElement`，窗口恢复后接着输入能写回；Obsidian 的按键范围栈里没有留下插件的范围；控制台没有错误。
- **阅读视图的分段**：块内的文字和图片行按 Markdown 的规则分成几段（相邻的行合成一段，空行、标题、列表、引用各自成段）。有文字栏的块整个画在块内第一行所在的段里，块内其他的段清空，高度为 0。文字变了时 Obsidian 只重绘文字所在的段，画着布局的那一段不会更新。插件因此记下每篇笔记里画出来的布局依据的内容：所有块的注释行，以及每个有文字栏的块的全部行。只有真正画布局时才更新这份记录，清空的段不更新；`changed` 事件里有一项和记录不同，就重绘阅读视图。实测：在实时预览里改 B 右栏里单独成段的引用，阅读视图随即显示新文字，而且只出现一次；清空的段也更新记录时，阅读视图一直显示旧文字。
- **高度表**：有文字栏的块和普通布局块一样，是按实际高度测量的块级部件。实测显示前后、显示源码时，高度表都零偏差。
