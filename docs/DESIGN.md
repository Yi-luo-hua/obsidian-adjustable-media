# 设计说明

本文说明 Adjustable Media 的存储格式、代码结构和写入规则，以及开发时在 Obsidian 里实测确认过的行为。

## 1. 存储格式

### 1.1 语法

```markdown
<!-- vml {"v":2,"rows":[{"height":240,"widths":[1,1.4],"captions":[null,"草图"]},{"width":0.6,"align":"center"}]} -->
![[beach.png]] ![草图](attachments/sketch.png)
![[clip.mp4]]
<!-- /vml -->
```

- **开始注释**：整行为 `<!-- vml {JSON} -->`，顶格书写；没有任何设置时写成 `<!-- vml -->`，只有块级设置、没有行设置时省略 `rows`（各版本都把缺少的 `rows` 读作没有行设置）。
- **结束注释**：整行为 `<!-- /vml -->`，顶格书写。
- **一行就是一行布局**：两条注释之间只有图片或视频嵌入（`![[…]]` 或 `![…](…)`）的非空行是一行布局，嵌入之间可以有空格，也可以紧挨着。空行会被忽略。
- **文字栏**：块内其他的行都是文字，按普通 Markdown 显示在图片旁边。第一行图片之前的文字排在左边一栏，最后一行图片之后的文字排在右边一栏，图片那一栏夹在中间，相当于 LaTeX 里并排的几个 minipage。嵌入的不是 Obsidian 支持的媒体格式（例如嵌入一篇笔记），或者嵌入后面还有别的文字，这一行也算文字。

  ```markdown
  <!-- vml {"v":2,"width":0.4} -->
  左边一栏，可以写多行、多段，
  也可以有标题、列表和引用。
  ![[beach.png]]
  右边一栏。
  <!-- /vml -->
  ```

- **文字块**：块里只有文字、没有图片时，整块文字是一栏（解析时记作左栏），按块宽显示，也可以像图片一样浮动环绕，相当于 `wrapfigure` 里放一个 minipage。没有图片也没有文字的空块不接管。开始注释里写了 `"type":"text"` 的块整块都是文字：单独一行的图片也是文字（栏内的图），不会把块拆成文字栏。文字块可以分栏（`cols`），文字在各栏之间自动流动、平衡高度，相当于 `multicols`。

  ```markdown
  <!-- vml {"v":2,"wrap":"right"} -->
  **旁注**：靠右浮动的一栏文字，
  - 可以有列表。

  <!-- /vml -->
  ```

- 文字写在两行图片之间，这个块就判为无效：插件不接管，交给 Obsidian 按普通 Markdown 显示。
- 文字以列表结尾、紧挨着结束注释时，阅读视图会把结束注释和块后面的正文都读进列表的最后一项（1.13.7 实测；引用和普通段落不会）。插件写入的文字（包成布局块的命令、在布局里直接输入）以列表结尾时，在结束注释前留一个空行；块内空行本来就被忽略。
- 围栏代码（`` ``` ``、`~~~`，包括写在列表标记后面的）、frontmatter、`$$` 公式和注释（`%%`、多行 HTML 注释）里的内容一律不识别：里面的开始、结束注释都不算。块内的代码、公式和注释是块的文字（其中的嵌入也是文字）；块只在正文里的结束注释处结束，所以没有闭合的代码围栏会让块读不到结尾，插件不接管。0.3.1 及更早的版本遇到块内的代码、公式、注释时整块不接管。
- 插件写入时一行最多 4 个嵌入；手写超过 4 个时按 4 个一行折行显示，但不改动文件。
- 写入 JSON 时，`--` 转义成 `-\u002d`（避免提前闭合注释），`%` 转义成 `\u0025`（避免奇数个 `%%` 让整行被当成 Obsidian 注释）。`JSON.parse` 能正常读回。

### 1.2 元数据字段

`rows[i]` 对应块内第 i 行图片，文字行不算在内。

| 字段 | 适用 | 含义 | 默认值 / 范围 |
| --- | --- | --- | --- |
| `v` | 块 | 格式版本 | `2` |
| `width` | 块 | 整个布局块占容器宽度的比例；有文字栏时是图片那一栏的宽度，文字栏分掉剩下的；文字块是文字那一栏的宽度 | 占满；0.2～1，占满时不写。环绕或有文字栏时不写即为 0.4，最宽 0.8 |
| `wrap` | 块 | 文字环绕：布局块浮到 `left` 或 `right` 一侧，笔记自己的正文从旁边绕过，超出图片高度后恢复整行宽度 | 不环绕 |
| `skip` | 块 | 环绕的布局块从所在位置往下错开几行才开始，上面这几行保持整行宽度 | 0；1～40，没有 `wrap` 时不写 |
| `valign` | 块 | 文字栏和图片在竖直方向上怎样对齐：`center` 居中，`bottom` 靠下 | 靠上；没有文字栏时（包括文字块）不写 |
| `type` | 块 | `text`：整块都是文字，图片行也是文字 | 不写；按块的内容判断 |
| `cols` | 文字块 | 文字分几栏 | 1；2～4 |
| `gap` | 文字块 | 栏间距（em） | 2；0～6，只有分栏时才写 |
| `textAlign` | 块 | 文字对齐：`center`、`right`、`justify`（两端对齐），文字块和文字栏都适用 | 左对齐 |
| `size` | 块 | 文字字号，相对正文的倍数 | 1；0.5～2 |
| `align` | 块 | 不环绕、比容器窄的块放在哪里：`center`、`right`（图片块也适用；有文字栏的块不适用） | 靠左 |
| `height` | 行 | 行高（px） | 220；80～900 |
| `widths` | 多图行 | 各列宽度比例，按嵌入顺序 | 按媒体宽高比分配 |
| `width` | 单图行 | 占所在行宽度的比例 | 嵌入里写的尺寸，否则原图大小；0.1～1 |
| `align` | 单图行 | `left` / `center` / `right` | `center` |
| `offset` | 单图行 | 自由水平位置：图片左边的空白占整行空白的比例，0 靠左、1 靠右；有它时忽略 `align` | 0～1 |
| `captions` | 行 | 各项图注，`null` 表示没有 | 无 |
| `captionAlign` | 行 | `left` / `center` | `left` |

只写用户实际设置过的字段，尽量让开始注释短。不认识的字段写回时原样保留。数值保留 3 位小数。

单图的水平位置正好是靠左、居中、靠右时写成 `align`，旧版本插件也能读懂；停在其他位置才写 `offset`。旧版本不认识 `offset` 和块级 `width`，会按居中、占满显示，写回时原样保留它们。

环绕的布局块紧贴在被环绕的正文上方书写（结束注释下一行就是正文），和 LaTeX 的 `wrapfigure` 一样：块在笔记里的位置决定图片从哪里开始，`skip` 再往下错开几行。旧版本不认识 `wrap` 和 `skip`，会按不环绕显示，写回时原样保留。没有插件时，图片显示在那段正文上方。

旧版本不认识 `type`、`cols`、`gap`、`textAlign`、`size` 和块级 `align`，写回时原样保留。

有文字栏的块不浮动：它的 `wrap` 和 `skip` 留在注释里、写回时原样保留，但不起作用；菜单里不提供环绕选项，整块移动时也只能放在段落之间。旧版本插件把有文字栏的块判为无效，交给 Obsidian 按普通 Markdown 显示，不会改写它。没有插件时，文字和图片按书写顺序上下排列。

文字块和图片块一样可以浮动：`wrap`、`skip`、`width` 都作用在文字那一栏上，不环绕时默认占满、环绕时默认 0.4。它的高度由文字决定，外框只有改宽度的手柄。0.3.1 及更早的版本把文字块判为无效（无效块不改写），显示成普通 Markdown。

### 1.3 容错规则

| 情况 | 处理 |
| --- | --- |
| JSON 解析失败，或 `v` 不是 2 | 按默认值显示并提示；**这个块不可编辑**，插件不会改写它 |
| 文字写在两行图片之间 | 这个块无效，交给 Obsidian 按普通 Markdown 显示，插件不改写它 |
| 块里没有图片也没有文字 | 不接管，按普通 Markdown 显示 |
| 块里的代码围栏、公式或多行注释没有闭合 | 读不到结束注释，不接管 |
| 交叉引用的标签没有出现在笔记里 | 引用显示为 `??`（红色） |
| 同一个标签写了两次 | 按第一次出现的位置编号 |
| `rows` 比实际行数少 | 多出的行用默认值 |
| `rows` 比实际行数多 | 忽略多出的部分；下次写回时去掉 |
| `widths` / `captions` 的长度和该行嵌入数不一致 | 这个字段对这一行无效 |
| 用户手工调整了嵌入顺序 | 设置按位置对应，可能错位，重新设置即可 |
| 文件被重命名 | Obsidian 更新嵌入文本，嵌入数量不变，设置仍然对得上 |

### 1.4 编号与交叉引用

图、表和公式的编号与引用沿用 pandoc-crossref 的写法，草稿可以直接用 pandoc 转成 LaTeX（`src/markdown/crossref.ts`）：

```markdown
<!-- vml {"v":2,"rows":[{"captions":["不同模型规模下的零样本表现。 {#fig:scaling}"]}]} -->
![[scaling.png]]
<!-- /vml -->

$$
p(x) = \prod_i p(s_i \mid s_{<i}) \label{eq:lm}
$$

| 参数量 | 层数 |
| --- | --- |
| 117M | 12 |

四种模型的结构。 {#tbl:arch}

如 @fig:scaling 所示，模型按 @eq:lm 训练，结构见 @tbl:arch。
```

- **图注、表注**：段落末尾的 `{#fig:名字}`、`{#tbl:名字}` 表示这一段是第 N 个图或表的说明文字。显示时标签隐藏，段首加上“图 N”“Figure N.”，段落缩小字号。布局块的图注（开始注释里的 `captions`）也可以写标签，并且按 Markdown 显示。
- **公式**：`$$` 公式里的 `\label{eq:名字}` 表示第 N 个公式。显示时标签换成 `\tag{N}`；已有 `\tag`、`\notag`、`\nonumber` 的公式不再加编号，标签照样去掉。标签从不交给 MathJax：MathJax 会全局记住画过的标签，同一个公式重画时报“标签重复定义”，整个公式显示成源码（实测）。
- **引用**：`@fig:名字`、`@tbl:名字`、`@eq:名字` 显示为“图 N”“表 N”“式 (N)”（英文为 Figure N、Table N、Eq. (N)），点击后目标滚到视图中间，光标不动（实时预览里光标移进布局块会显示块的源码）。目标还没画出来时，实时预览用 CodeMirror 的 `scrollIntoView` 效果滚到那一行，阅读视图用 `setEphemeralState({ line })`，再把画出来的目标滚到中间。找不到目标时显示红色的 `??`。邮箱地址（`a@fig:b`）不算引用。
- **编号**：按标签在笔记里出现的先后，每种各自从 1 开始；代码里的不算。编号的语言在设置里选（跟随 Obsidian、English、中文）。笔记里没有任何标签和引用时，插件不做这些处理。
- **显示位置**：布局块里的文字和图注在交给 Obsidian 渲染之前改写 Markdown（`numberMarkdown`），编号变了就整体重画这些布局。块外的正文，阅读视图在后处理器里改写画好的文字节点，带标签的公式段用 `renderMath` 重画；实时预览用装饰替换引用和标签，带标签的公式块整块换成带编号的公式（`Prec.high`，盖过 Obsidian 自己的公式），光标碰到时显示源码。只改显示，笔记里的标签原样保留。
- **限制**：实时预览里标注框（callout）内的引用由 Obsidian 自己的部件渲染，插件的后处理器能改写（实测可以），但点击会先让标注框显示源码。只在这篇笔记内编号，不跨笔记。

## 2. 代码结构

| 模块 | 职责 |
| --- | --- |
| `src/markdown/lineContext.ts` | 单遍扫描，判断每一行是正文、代码、frontmatter、公式还是注释 |
| `src/markdown/columnStyle.ts` | 文字栏编辑器怎样照实时预览画 Markdown：每个记号带哪些样式类，哪些标记在光标不在时隐藏，列表符号、任务方框、引用、链接、公式和嵌入的画法，折行后的行悬挂在哪几个字符下面 |
| `src/markdown/columnEditing.ts` | 文字栏编辑器的按键和 Obsidian 的编辑命令：Tab 在引用标记之后整行缩进，回车接续列表和引用，加粗等格式的开关，链接、标签、列表、任务、引用和标题命令改写的文字，快捷键的名字，以及 `[[` 之后正在输入的链接 |
| `src/markdown/crossref.ts` | 图、表、公式的标签、编号和引用：收集标签，把 Markdown 改写成带编号的样子 |
| `src/format/v2.ts` | 识别布局块、解析嵌入（保留原文和列位置）和图片两侧的文字、读写元数据 |
| `src/layout/model.ts` | 布局模型和操作：移动、插入、移除、行高、列宽、单图宽度与位置、块宽度、整体缩放、图注、文字环绕与错开行数、文字栏的竖直对齐 |
| `src/layout/drawn.ts` | 阅读视图里画出来的布局依据了笔记的哪些内容，笔记变化后是否需要整体重绘 |
| `src/layout/edits.ts` | 把模型变化规划成行级修改（文字栏原样保留），添加文字栏时的空行，并在写入前定位、核对 |
| `src/layout/placement.ts` | 整块移动：块可以落在哪些位置，以及移动时的修改规划 |
| `src/layout/plainEmbed.ts` | 从块外的普通媒体行里取出一个嵌入，供拖进布局块 |
| `src/layout/writeBack.ts` | 唯一的写入入口 |
| `src/layout/geometry.ts` | 拖拽落点、列宽计算、单图水平位置与吸附、整块移动时的环绕方向和错开行数 |
| `src/layout/wrapGaps.ts` | 实时预览里环绕排版的几何规划：被推到浮动下方的元素前的占位，以及锚点不在渲染范围时的替身浮动 |
| `src/view/` | 布局渲染（阅读视图和实时预览共用，文字栏由 Obsidian 的 `MarkdownRenderer` 渲染）、实时预览里文字栏的直接编辑（`textEditing.ts`；编辑器本身在 `columnEditor.ts`，按键在 `columnKeys.ts`，公式、图片和任务方框在 `columnWidgets.ts`，悬挂缩进在 `hangingIndent.ts`，链接建议在 `linkSuggest.ts`，读取 Obsidian 未公开的设置和快捷键在 `obsidianInternals.ts`）、实时预览里的交互（拖动、调整大小、范围框、整块移动；阅读视图只显示布局）、实时预览和阅读视图里环绕排版的维护（`wrapGuard.ts`、`readingWrap.ts`）、块外图片拖入、图片右键菜单、看图、弹窗、界面文字 |
| `src/view/crossrefView.ts`、`src/view/math.ts`、`src/view/textLayoutModal.ts` | 编号与引用的显示和跳转；等 MathJax 加载后再画公式；文字设置弹窗 |
| `src/input/` | 拖入 / 粘贴后的自动转换 |
| `src/commands/` | 命令 |

数据流：笔记文本 → `lineContext` → `v2` 解析出块 → `model` → 视图渲染；用户操作 → `model` 的操作函数得到新模型 → `edits` 规划修改 → `writeBack` 写入 → Obsidian 重新渲染。

`src/view/`、`src/input/autoConvert.ts`、`src/commands/register.ts` 依赖 Obsidian 接口；其余模块都是纯函数，由 `tests/` 里的测试覆盖。

## 3. 写入规则

1. 永远不改写嵌入文本和文字栏里的文字，只改开始注释，或者把嵌入整段搬走。
2. 每次修改都锚定在块渲染时的完整原文上。写入前，原文必须仍在原来的行上；如果笔记上方有改动导致块整体下移，就在正文里查找这段原文，**恰好出现一次**才写入（代码块里的副本不算）。找不到、不止一处、或同一次操作里两个修改指向同一个块，都放弃写入并提示。
3. 只改设置时只重写开始注释这一行，块内原有的空格、空行保持不变；嵌入的分布变了才重写整块。有文字栏的块重写时，第一行图片之前和最后一行图片之后的内容（文字连同其中的空行）逐字保留，只换掉中间的图片行。块里最后一个嵌入被移走时，只去掉注释和图片，左右两栏的文字作为普通段落留在原处，中间隔一个空行。删除整块时只顺带去掉周围多出的一个空行。块以外的内容一律不碰，CRLF 文件保持原有换行符。
4. 笔记在某个窗格里处于源码或实时预览模式时，通过那个编辑器的一次事务写入（可以撤销，不会丢掉没保存的输入）；否则用 `vault.process` 直接改文件。在布局里直接输入的文字不经过 Obsidian 的 `editor.transaction`，而是按字符位置换算后由那个编辑器的 CodeMirror 视图 `dispatch`，`userEvent` 为 `input.type`（和打字一样，连续输入合成一步撤销），不带 `scrollIntoView`：`editor.transaction` 会把笔记滚到笔记自己的光标处，光标离正在输入的布局远时，布局被滚出视图、编辑器随之关闭（2026-09-17 实测：`scrollTop` 从 6649 跳到 747）。
5. 渲染时从不写文件。
6. 把块外的图片拖进布局块时，两处修改在同一次写入里完成：从原来那行取走嵌入（这一行只剩空白就整行删除，并顺带去掉周围多出的一个空行；否则只去掉嵌入和它后面的空格），再写进目标块。原来那行同样以原文锚定、核对，两处有一处对不上就都不写。只有整行都是媒体嵌入、位于正文、不在任何布局块里的行才能取出嵌入。
7. 整块移动布局块时，同样是一次写入里的两处修改：块从原处整段移走（两侧都是空行时顺带去掉一个，位于笔记开头时去掉后面的空行），再原样插到目标行前面，只有开始注释可能因为环绕方向、错开行数改变而重写。目标行连同它上面一行一起作为锚点核对。块只能落在顶层 Markdown 块的开头（空行、标题、另一个布局块或代码、公式、注释、frontmatter 结束之后的正文行）或笔记末尾，不会插进列表、缩进内容、代码、公式、注释和其他布局块中间。插入时块前面补一个空行；不环绕的块后面也补一个空行，环绕的块紧贴在它环绕的正文上方。目标就是原位时只改开始注释。
8. 在布局里直接编辑文字栏时，插件把文字栏编辑器里的文字写回这一栏自己的行：从这一栏的第一行到最后一行；这一侧还没有文字时，左栏插在开始注释后面，右栏插在结束注释前面；编辑器清空时去掉这些行。首尾的空行不写，只有一处例外：文字以列表结尾、下一行就是结束注释时，在它们之间留一个空行（见 1.1）。文字块只有一栏，不会被清空：清空时不写入，编辑器的框标红。每次写入同样锚定块的原文、核对后才写，而且写之前先检查：写入后这个块必须还能读回原来的开始注释、图片行和另一侧的文字，这一侧读回的正好是输入的文字。输入了只有图片的一行、代码围栏、`%%` 或布局注释这类会改变块结构的内容时不写入，编辑器的框标红并提示。
9. 「把选中的内容包成布局块」命令：选中的非空行都是媒体嵌入时，照旧把嵌入合并成图片行（每行最多 4 个）。有文字的行则从第一个非空行到最后一个非空行原样包进去（中间的空行、代码、公式和注释都保留），只在前后加开始、结束注释：只有文字时写成 `"type":"text"` 的文字块；文字在图片前后时是文字栏；文字夹在两行图片之间时改为 `"type":"text"` 的文字块，图片是栏内的图。写入前检查：这些行不在任何布局块里，加注释后的笔记在这里读出恰好一个可编辑的块，正好包住这些行，其他块一个不多一个不少。所以选区只包含代码围栏、公式或多行注释的开头（结束注释会落进里面）、或者包含布局注释时不包。
10. 有文字栏的块和文字块不参与合并：「与下一个布局块合并」命令拒绝合并，拖入、粘贴的新图片也不并入它，而是自成一个块。否则一个块的文字会落到另一个块的两行图片之间，块就无效了。

## 4. 实测确认过的 Obsidian 行为

开发时在测试库（Obsidian 1.13.7）里验证过，设计依赖这些结论：

- **阅读视图的分段**：开始注释、嵌入行、结束注释各是一个独立的段（开始注释下一行不需要空行，结束注释会截断段落），`getSectionInfo` 给出的行号准确。被嵌入到其他笔记里的内容没有段信息，保持 Obsidian 自己的渲染。
- **阅读视图只重绘变了的段**：文字没变的段会沿用旧的渲染结果。只改设置时，变的只有开始注释那一段，嵌入所在的段不会重新经过插件，于是继续显示旧布局，而且下一次修改会因为锚定的原文对不上而失败。插件因此在 `metadataCache` 的 `changed` 事件里比较这篇笔记的布局块注释行（有文字栏的块比较它的全部行，见 4.2），有变化就对显示这篇笔记的阅读视图调用 `previewMode.rerender(true)`（实测：`changed` 触发时视图已拿到新内容，`rerender(true)` 后显示正确）。
- **实时预览**：`StateField` 提供的块级替换装饰（`Prec.high`）能盖住 Obsidian 自己的图片嵌入组件；选区碰到块时取消替换即可显示源码。
- **阅读视图下不能写编辑器**：阅读模式的视图仍然有编辑器对象，但写它只会改到隐藏的内容，既不存盘也不刷新，切到别的笔记时修改会被丢弃。所以阅读模式下改用 `vault.process`。
- **注释的可见性**：不装插件时，阅读视图不显示 `<!-- -->` 注释，实时预览显示成灰字。同一行的大图在没有插件时会上下排列。
- **重命名**：重命名块内的图片后，Obsidian 会更新嵌入文本，Markdown 链接会按「最短路径」改写，块结构不受影响。
- **拖入 / 粘贴附件**：Obsidian 依次触发 `editor-drop` / `editor-paste`（带文件名），把附件存进库里，再用一个**没有 `userEvent`** 的事务插入 `![[文件名]]`，全程几十毫秒。一次拖入多个文件时，每个文件单独一个事务，除最后一个外都带一个空行。事件里的光标位置不可靠。自动转换因此按「记下预期数量 → 收集随后没有 `userEvent` 的嵌入插入」来实现。预期数量取自编辑器上的 DOM `drop` / `paste` 事件（CM6 `domEventHandlers`，最高优先级，只读取文件列表，不处理也不拦截事件），而不是 `editor-drop` / `editor-paste`：官方审核规则要求这两个事件的处理函数调用 `preventDefault()`，而那样会让 Obsidian 不再插入附件。
- **从 Obsidian 文件列表拖入**：`drop` 事件的 `dataTransfer` 里没有文件，Obsidian 用一个没有 `userEvent` 的事务直接插入 `![[文件名]]`。所以没有文件的 `drop` 也会开一个 2 秒的短窗口，数量未知，最后一次插入之后稍等再转换；拖入的是笔记或文字时插入的不是媒体嵌入，窗口到期作废。
- **文件右键菜单**：对媒体文件触发 `workspace.trigger("file-menu", menu, file, "link-context-menu")`，Obsidian 会加上「在文件列表中显示当前文件」「在系统资源管理器中显示」「在新窗口中打开」「复制路径」等项（1.13.7 实测），不需要调用文件列表的内部方法。
- **发布到 Hexo**：`marked` 会把 `<!-- vml … -->` 原样输出为 HTML 注释，页面上不可见。
- **实时预览里的普通图片**（1.13.7 实测）：单击图片会选中它（容器加上 `is-selected`），并把光标放到嵌入开头；再单击一次打开 Obsidian 自带的看图灯箱。「包成布局块」命令因此可以直接作用于刚点过的图片，用户给命令绑个快捷键即可（插件不设默认快捷键）。图片还带有 Obsidian 自己的缩放角和右键菜单；桌面端 `img` 默认可以被浏览器原生拖动。
- **图片右键菜单**：Obsidian 为实时预览里的图片弹出自己的菜单时，会在 `contextmenu` 事件里同步触发 `file-menu`（来源 `link-context-menu`），但不带被点的是哪一个嵌入。插件在捕获阶段记下 `contextmenu` 的目标元素，在 `file-menu` 里用 `EditorView.findFromDOM` 和 `posAtDOM` 找回它所在的行，再加上「包成布局块」。
- **块外图片的拖动**：插件直接在编辑器的 DOM 上监听 `pointerdown`，不依赖 CodeMirror 是否把图片部件里的事件交给扩展；指针移动超过阈值才接管，所以 Obsidian 的单击选中、缩放角和菜单不受影响。插件跟随拖动期间，浏览器原生的图片拖动必须取消，否则它会接管手势，并在松手处插入图片地址。取消要在捕获阶段、在编辑器的 `contentDOM` 上完成（`preventDefault` 加 `stopPropagation`）：Obsidian 的拖动管理器（`dragManager.handleDrag`）把 `dragstart` 监听直接挂在图片元素上，一收到就给 `body` 加上 `is-grabbing`（全局 `cursor: grabbing !important`）并记下 `dragManager.draggable`，两者都只在原生 `dragend` 时撤销。如果在冒泡阶段才取消，拖动已经由 Obsidian 开始，却永远等不到 `dragend`，指针会一直停在抓握状态（1.13.7 实测）。插件没在跟随拖动时不拦截，Obsidian 自己的图片拖动照常工作。拖动结束后浏览器仍会在松手处补发一次 `click`，插件把这次点击吞掉，免得实时预览选中松手处的图片。
- **阅读视图的灯箱**：阅读视图对段落里任何没被 `preventDefault` 的 `img` 单击都会打开灯箱，插件画的布局图片也一样，所以阅读视图不另做看图。实时预览的灯箱只认 Obsidian 自己的图片部件，插件调用不到，因此自带一个看图弹窗（双击打开）。全屏的 `Modal` 在 1.13.7 里没有自带的关闭按钮，看图弹窗自己画一个。
- **阅读视图只显示布局**：拖动、调整大小、右键菜单和文字栏的直接编辑都只在实时预览里，阅读视图里的布局不挂任何交互。实测（1.13.7，用 DevTools 协议发送真实的点击和拖动）：`text-test.md` 的四个布局都没有手柄，右键不弹任何菜单（Obsidian 在阅读视图里也不给这些图片弹菜单），拖动图片什么也不跟随，单击文字栏不进入编辑，单击图片照常打开 Obsidian 的灯箱（`lightbox`，和普通嵌入的图片一样）。

### 4.1 文字环绕

环绕用 CSS 浮动实现：布局块浮到一侧，笔记自己的段落从旁边绕过。以下都在测试库（1.13.7）里逐项测过，缺一项都会出错。

- **阅读视图**：浮动会自己溢出所在的段，后面各段的文字直接绕排，不需要额外处理。代码块和表格本身就是独立的格式化上下文，会自动缩窄排在图片旁边。引用块的竖线、Callout 的底色、分隔线和行间公式会被压在图片下面，嵌套列表会丢掉缩进，所以笔记里有环绕的块时，这几种元素改成 `display: flow-root`，作为一个整体排在图片旁边。哪篇笔记有环绕的块由后处理器判断，它给这篇笔记的每一段加上类 `vml-rv-wrapping`；不用 `:has()`，插件审核的 CSS 检查会因为性能对它报警告。Obsidian 只重画文字变了的段，其余的段沿用原来的渲染结果，不再经过后处理器。所以笔记加上第一个环绕的块、或者去掉最后一个时，插件在后处理器里发现这个变化：它按阅读视图的 `docId` 记下这个视图上次画的是哪篇笔记、有没有环绕。发现以后，它给这个阅读视图的所有段改类；段列表读自 Obsidian 的渲染器，读不到时让这篇笔记的阅读视图整体重画。实测：没有这一步时，在已有列表、引用、Callout、分隔线的笔记里插入第一个环绕的块，这些元素仍是 `display: block`，要强制重画才恢复。Obsidian 的标题不清除浮动。
- **实时预览的锚点**：CodeMirror 把各行和各部件的高度逐个加起来，得到每个元素的位置（高度表），点击定位、方向键和虚拟渲染都依赖它。环绕的块的部件高度为 0，只作为锚点，布局块从里面浮出去。旁边的行按各自的实际高度测量，高度表因此保持准确。实测：行位置零偏差，旁边文字的点击定位、上下方向键、在旁边打字时的实时重排都正确。
- **实时预览里要改掉的四处 Obsidian 样式**：
  1. Obsidian 给所有块级部件设了 `contain: paint !important`（`.cm-content > [contenteditable=false]`），浮动会被关在部件里。环绕的块用选择器更具体的规则取消，而且这条规则也必须带 `!important`：带 `!important` 的声明只有另一条 `!important` 能盖过。插件审核的 CSS 检查会对它报"避免 `!important`"的警告，这是唯一必须保留的地方（不环绕的块在有环绕的笔记里同理）。
  2. 编辑器的行是 `position: relative`，定位元素绘制和接收点击的层级都在浮动之上，点图片会点到文字。浮动设 `z-index: 1`。
  3. 标题、代码块、分隔线和脚注的行带 `clear: left`，会被推到图片下面，推开的空隙不属于任何元素，高度表从这里开始整体偏移（实测 77px）。笔记里有环绕的块时，行不再清除浮动，标题也照常绕排。
  4. 列表、引用的悬挂缩进是 Obsidian 渲染时实测出来、写在行内样式里的。在图片旁边量，会把图片宽度也算进去（实测 327px），列表第一行滑到图片底下。这些行改成 `display: flow-root`，作为一个整体排在图片旁边，从自己的边缘量。
- **外边距**：CodeMirror 只量元素的盒子，不算外边距。去掉 `contain` 后，布局块自己的外边距会穿出部件，后面每一行都偏移 12px，所以实时预览里布局块的上下间距改用部件的内边距。不环绕的布局块要排到浮动下方，它的清除间距也留在部件内部，由 CodeMirror 量到。
- **放不到图片旁边的元素**：宽度不够、只能排到浮动下方的部件，推开的空隙同样不属于任何元素。`wrapGuard.ts` 在每次测量后比较各元素的实际位置和高度表，发现这种空隙就在该元素前插一个同样高的占位部件，浮动变化时占位跟着变高、变矮或移除。块级部件只能由状态字段提供，所以占位通过状态效果写入。实测里 Obsidian 的表格和 Callout 都能缩窄排在旁边，这个机制作为兜底。
- **很高的浮动**：CodeMirror 只渲染视口附近的内容；跳转时只往目标上方多渲染约 500px。浮动的锚点不在渲染范围、浮动却伸进来时，旁边的行会失去绕排，等锚点渲染出来再跳回去。`wrapGuard.ts` 记住每个浮动的尺寸，这时在第一条渲染出来的行上放一个同样大小、只显示下半截的替身浮动。实测：跳到 605px 高的浮动下半截旁边再往上滚 800px，文字零跳动，替身和真浮动交接时也不动。
- **显示源码时**：块显示源码后，Obsidian 会把块里的嵌入按原尺寸渲染成图片（实测一张竖图 1244px 高），整篇笔记跟着大幅移动。所以块的每一行带上 `vml-source-line`，其中的图片、视频缩成缩略图；环绕的块还在第一行开头放一个只读的浮动，源码行排在它旁边，后面的文字继续绕排。实测显示源码时正文只下移约 120px，且保持绕排。
- **错开行数**：`skip` 用一个宽度为 0 的浮动把布局块往下垫，高度按 `lh` 单位（行高）计算，被垫过的行保持整行宽度。
- **多个浮动**：左右各一个浮动时，正文从两者中间穿过；一个高浮动旁边再开始一个另一侧的浮动，或者同一侧上下两个浮动（后一个排在前一个下方），都照常绕排。上面的机制按浮动逐个处理，不需要额外的规则。实测（测试库的 `wrap-multi.md`）：实时预览来回滚动三轮，高度表零偏差，跳到两个高浮动的下半截时两个替身同时生效；阅读视图以 40px 步长来回滚动三轮，没有文字失去绕排，也没有跳动。
- **阅读视图的虚拟渲染**：阅读视图也只把视口附近的段留在页面里（`updateVirtualDisplay`），每段的高度记为到下一段顶端的距离（`measureSection`）。环绕的布局块所在的段因此是 0 高，渲染范围的上边界一越过它的顶端它就被收起，而旁边的文字因为自己有高度还留着，于是失去绕排，下面的内容整体移动（实测：紧跟一个不环绕的块时移动 198px，正是清除浮动的距离）。`readingWrap.ts` 在布局块那段还在页面里时，给浮动旁边的每一段预先放一个隐藏的替身（与实时预览的替身同一套尺寸规划），标出布局块那段和这些段。CSS 只让"紧挨在前面的段既不是布局块那段、也不是另一个带替身的段"的那个段显示替身，也就是这一片里第一个还留在页面里的段。Obsidian 收起布局块那段的同一刻，替身就生效了，它随后测量各段时量到的仍是绕排后的高度。替身必须事先放好：`updateVirtualDisplay` 在同一个同步调用里收起段并立即测量，`MutationObserver` 的回调来不及（实测：来不及时下一次收起这些段会再跳 234px）。替身的外层用 `display: contents`，不改变外边距的折叠。Obsidian 按记录的高度算位置，布局块那段本来就记为 0，替身不影响它的计算。
  - 后台测量：笔记打开后，Obsidian 还会在后台把所有段画出来、量好高度（`onRender`）：每次画一批（大约十段），把这一批临时放进页面，量完就拿走。布局块那段和它旁边的文字分在两批时，量后一批的时候布局块不在页面里，文字按整行宽量出来，偏矮。第一次滚进这里时（例如从笔记末尾往上滚），文字又比布局块那段先进入页面，替身却还没放，于是先按整行宽排，布局块进来时再改成绕排。两种情况都会跳。实测（`wrap-test.md` 和 `wrap-multi.md`：打开后直接到末尾，等后台量完，再以 40px 步长滚到顶）：分别跳了 8 次，最多 312px 和 336px；第二遍一次都不跳。
  - 所以替身也按 Obsidian 已经量好的高度来规划，高度读自 Obsidian 未公开的阅读视图渲染器（每段的 `el`、`height`、`computed`、`rendered`、`shown`，见 `obsidianInternals.ts`）。每段画完、Obsidian 量它之前，插件在后处理器里把前面各段的高度加起来，算出浮动在这一段旁边的部分，放好替身；这一批量完以后（下一个微任务），再补上这一批里其他的段。布局块在页面里时，和它一起在页面里的段仍按实际位置规划。
  - 一批段和显示范围同时在页面里：Obsidian 量新画的一批段时，当前显示的段也留在页面里，两者之间隔着没放进来的段（例如显示笔记开头 0–23 段，同时量 51–81 段）。CSS 规则原来看"前面任何位置有没有布局块那段或带替身的段"，显示范围里另一处环绕的段也算，这一批里第一个带替身的段就不显示替身，文字按整行宽量出来，量完又离开页面，不会再被纠正。实测：笔记打开时 Obsidian 先在开头显示、在后台测量，之后才滚到保存的位置；`wrap-multi.md` 的 M3 旁边三段因此记成 88px（实际 112px），从末尾往上滚时跳 48px 和 24px，大约一半的打开会遇到，和插件的其他改动无关。所以规则只看紧挨在前面的那一段：同一处环绕的段在笔记里是连着的，结果和原来一样；隔着空缺时，前一片的段不再影响后一片。仍然没有解决的情况：显示范围的最后一段正好在一处环绕的中间时，后一片的第一段同样不显示替身，前一片的浮动还会伸进后一片。
  - 浮动的尺寸：布局块在页面里时量它本身；不在页面里时，把它那段复制一份，放进页面里一个高度为 0 的盒子里，量完就拿走（`vml-rv-measure`）。同一侧的浮动像页面里一样上下相接：真实的布局块带 `clear: left` 或 `clear: right`，后一个浮动从前面同侧浮动的底边以下开始，规划时同样处理。图片、视频还没有尺寸时（插件第一次见到这张图，要等它加载完才知道高度），先不规划，等加载完再规划，并让 Obsidian 重新量浮动旁边那些段：对这些段调用渲染器的 `resetCompute`，再 `queueRender`，和窗口宽度变了时 Obsidian 自己做的一样。取不到这些内部数据时，只有布局块在页面里时放的替身，和以前一样。
  - 打开时停在中间：Obsidian 每次改变页面里留哪些段（`updateVirtualDisplay`），都在同一个同步调用里先收起范围外的段，再重新测量页面里的每一段。笔记打开时直接停在布局块下方（例如打开后直接到末尾），布局块那段第一次画出来、量完、又被收起，都在同一个任务里，插件来不及规划替身，旁边的文字就按整行宽量了。实测（`wrap-multi.md` 最后两个浮动旁边的五段）：先连同布局块量出 160、160、88、136、160px，一毫秒后按整行宽重量成 64、64、64、88、88px。这些段在 Obsidian 下次测量前离开页面，笔记就跳，差值正是之前偶尔出现的 96px。所以每次规划完替身，插件都把页面里各段画出的高度（到下一段顶端的距离，算法同 `measureSection`）和 Obsidian 记的高度对一遍：有不一致的，先按画出的高度重新规划后面的替身，再让 Obsidian 重新测量这些段（同样是 `resetCompute` 加 `queueRender`）。Obsidian 重新测量之前，会先把还没画的段画出来，插件要按这些段的高度给新画的段规划替身，所以在它量完之前，这些段按画出的高度计算；否则它们算作未知高度，新画的段放不上替身，按整行宽量出来，又离开了页面，不会再被纠正（实测：`wrap-multi.md` 的 M3 旁边三段因此记成 88px，实际 112px，往上滚时跳了 48px 和 24px）。同一段、同样的两个高度，在看到 Obsidian 量对之前只请求一次，免得 Obsidian 量得和画出的总不一样时反复请求。
  - 替身画得准不准：`wrap-multi.md` 的 M2、M4 旁边每一段，逐段只显示这一段的替身、藏起真浮动，和真浮动时比：各段高度、每行的宽度都一样。只有左右两个浮动从同一行开始时，右边的替身比真浮动低 4px（前一个替身的"沙袋"把后一个挤下去），这两处都不改变任何高度。
  - 实测同样的滚动（每次新打开、直接到末尾、等后台量完，再以 40px 步长滚到顶），改过以后：`wrap-multi.md` 7 次里 5 次零跳动，另外 2 次各跳一次（M2 一段 24px、M4 一段 48px，原因还没查清，可能就是上面没有解决的那种情况）。同样的测试，用只看"前面任何位置"的旧规则时大约一半会在 M3 跳 48px 和 24px，不做页面里的核对时还会在 M4 跳 96px。`wrap-test.md` 每次剩一次 31–32px，来自 Obsidian 延迟渲染的公式块（第一次显示时从 49px 变成 81px，和环绕无关，没有插件也一样）；还有一次 4–5px：C 里紧跟浮动的不环绕布局块，按替身量出来比按真浮动矮 4px，原因还没查清。第二遍都零跳动；原来的来回滚动测试（`wrap-test.md` 的 D）和多浮动测试（`wrap-multi.md` 往下、往上、再往下）照常零跳动，也没有文字失去绕排。

### 4.2 文字栏

以下同样在测试库（1.13.7）里测过。

- **渲染**：文字栏由 Obsidian 的 `MarkdownRenderer.render` 渲染，标题、列表、引用、链接和嵌入都和正文显示得一样。渲染结果挂在一个 `Component` 上：实时预览里是部件自己的，部件销毁时一起卸载；阅读视图里是这一段的 `MarkdownRenderChild`。
- **实时预览里的空白**：编辑器内容区是 `white-space: pre-wrap`，Obsidian 渲染结果里元素之间的换行会显示成空行（实测一栏有标题、段落和列表时高出 65px，列表项之间也被拉开）。文字栏改成 `white-space: normal`。
- **实时预览里的链接**：文字栏里的链接由 Obsidian 自己处理：单击在当前标签页打开，Ctrl+单击打开一个新标签页，悬停显示页面预览。插件如果也处理，会打开两个标签页，所以插件不处理链接。
- **在布局里直接编辑**（实时预览，`textEditing.ts`、`columnEditor.ts`）：点文字栏时，只有这一栏换成一个编辑器，显示这一栏的源码，布局其余部分不动；拖选文字复制时不切换。插件写不进的块（设置读不懂）点文字仍然显示整块源码。
  - 编辑器是嵌在布局部件里的另一个 CodeMirror 编辑器。笔记的编辑器不管部件里的 DOM 变化和事件：`WidgetView` 和 `BlockWidgetView` 的 `ignoreMutation` 恒为 true，`ignoreEvent` 交给部件（布局部件恒为 true）；焦点在里面的编辑器上时，它也不读选区（`onSelectionChange` 只认自己的 `contentDOM`）。两个编辑器因此互不干扰。
  - 样式和笔记的编辑器一样。Obsidian 的 Markdown 语言可以用 `@codemirror/language` 公开的 `language` facet 从笔记编辑器的状态里取到（一个名为 `hypermd` 的 `StreamLanguage`），装进另一个 `EditorState` 后，解析结果和笔记编辑器逐个记号相同。每个记号的名字是它的各个样式用 `_` 连起来，笔记的编辑器给记号的文字加上「`cm-` 加样式名」的类，给所在的行加上以 `HyperMD-` 开头的样式名：`formatting_formatting-strong_strong` 画成 `cm-formatting cm-formatting-strong cm-strong`，`HyperMD-header_HyperMD-header-1` 是行上的 `HyperMD-header HyperMD-header-1`。编辑器按同样的规则加类，又位于笔记编辑器的 DOM 里，Obsidian 和主题写给笔记编辑器的 CSS 就原样作用在上面，标题字号、粗体、链接颜色、列表标记都和笔记里一样。实测：标题、粗体、斜体、删除线、高亮、行内代码、链接、内部链接、标签、公式、列表、任务、引用和 HTML 的记号名与类名全部对得上。取不到这个语言时（例如以后 Obsidian 换了实现），编辑器照样能输入，只是没有样式。
  - 标记按实时预览的画法处理（`columnStyle.ts`）。实测实时预览（1.13.7）：标题和引用的标记在光标所在的行上才显示；粗体、斜体、删除线、高亮、行内代码和链接的标记要等光标碰到这一段才显示，同一行的其他地方不算；不显示时这些标记画成空白，链接只剩文字（外面套一层 `cm-underline`）；引用的 `>` 变成透明（`cm-transparent`），竖线由行的 `::before` 画出，第二层起的 `>` 是 `cm-blockquote-border`；列表符号不论光标在哪都画成圆点或编号（`-` 外面套 `list-bullet`，`1. ` 外面套 `list-number`，样式来自 Obsidian 的 CSS）；任务的 `- [ ]` 换成一个复选框（`task-list-label` 里的 `task-list-item-checkbox`）；行内公式画成 MathJax 的渲染结果（`span.math` 里的 `mjx-container`），光标进到 `$` 之间才显示源码；嵌入画成图片，光标在嵌入的源码里时也仍然是图片。编辑器照这些规则加类、隐藏或换成部件（`columnWidgets.ts`）：公式用 Obsidian 的 `renderMath` 渲染，图片嵌入画成和画出来的文字栏一样的 `span.internal-embed` 里的 `img`（按 `|宽` 或 `|宽x高` 定尺寸），其他嵌入保留源码；公式和图片在光标碰到时显示源码，不然没法改。点复选框就在文字里改写 `[ ]` 或 `[x]`，焦点和光标都不动。点公式时光标放进公式里：MathJax 自己处理点击会把焦点从编辑器拿走，输入也就结束了，所以部件在捕获阶段接下 `mousedown` 和 `click`。
  - 折行：实时预览里列表项、任务、引用和开头有缩进的行折行后，后面几行从文字开始的地方排，不从标记下面排。Obsidian 量出这些标记画出来多宽，写进行内样式，例如 `text-indent: -23px; padding-inline-start: 23px`：`- ` 23px、`* ` 24px、`1. ` 29px、`10. ` 39px、`- [ ] ` 31px、`> ` 16px、`> > ` 33px、`> - [ ] ` 48px，每多一层缩进多 36px。算进去的是引用标记、缩进、列表符号连同后面的一个空格、任务方框：`-   项` 仍按 `- ` 算，标题不算。编辑器也这样量（`hangingIndent.ts`）：每次可能改变宽度的更新后，量这些字符之后的位置离行首多远（行首取行框的位置，不取第一个字符，因为 Obsidian 把圆点画在 `-` 以外的地方），通过类 `vml-hanging` 和 CSS 变量 `--vml-hanging` 设置。测量阶段不能发起更新，量好的宽度放到微任务里生效。实测：C 栏里折行的列表项第二行从 23.7px 开始，和第一行的文字对齐；引用是 16.6px。
  - 编辑器在笔记编辑器里，可读行宽的规则也作用在它上面（`max-width: 700px`），但文字栏总比笔记窄，这个限制不起作用。它的首行和画出来的文字栏一样没有上边距，其他标题行保留 Obsidian 给的上边距。实时预览里空行和别的行一样高（24px）；编辑器里光标不在的空行只有段落间距那么高（`--p-spacing`，16px），和画出来的文字栏一致。实测：进入编辑时文字的位置偏移不到 0.5px，这一栏的高度几乎不变：`text-test.md` 的 A 栏画出来 160px、编辑时 159px，B 栏 64px 和 63px（空行按整行算时 A 栏是 199px）。
  - 按键（`columnKeys.ts`，改写文字的部分在 `columnEditing.ts`）。实测笔记的编辑器（1.13.7）怎样做，编辑器就怎样做：
    - Tab 把光标所在的行整行缩进，不管光标在行里什么位置；有选区时是选区经过的每一行。引用行的缩进加在 `>` 后面：`> abc` 变成 `> \tabc`。Shift+Tab 去掉一级。缩进单位和制表符宽度取自笔记的编辑器。Tab 不再把焦点移出编辑器，用 Esc 退出。（这里之前记的「其他地方在光标处插入缩进」不对，已按实测改正。）有序列表的项缩进后 Obsidian 会把编号改成 1，编辑器不改。
    - 回车在列表项和引用行上接着写下一项：同样的符号、下一个编号、未勾选的方框；在空的项上回车时，缩进的项上移一级，不缩进的结束列表，空的引用行去掉一层 `>`。
    - 加粗、斜体、删除线、高亮、行内代码、行内公式：选中文字时两边加上标记，选区跨几行就每行各加一对；选区正好在一对标记里面或外面时，去掉这对标记。没有选中时：光标在这种格式里面就去掉它；在结束标记前面时光标跳到标记后面，文字不变；在开始标记后面时什么也不做；在一个词里或挨着一个词时给这个词加上标记（连续的中文算一个词，和 CodeMirror 的 `wordAt` 一样；光标在词尾时落到结束标记后面）；都不是就放进一对空标记。哪两个标记是一对由语法树决定，所以在粗体里按 Ctrl+I 不会把粗体的星号当成斜体的。和 Obsidian 不一样的一处：光标在一对空标记中间时再按一次，Obsidian 会再插进一个标记（`**|****`），编辑器把这对空标记拿掉。
    - 链接：Ctrl+K 把选中的文字变成 Markdown 链接的文字，光标停在填地址的括号里，选中的是网址也一样；没有选中时放进 `[]()`，光标在方括号里。「插入内部链接」「插入嵌入」把选中的文字放进 `[[ ]]`、`![[ ]]`，光标在 `]]` 前面；「添加标签」在选区开头放一个 `#`。
    - 列表、任务、引用、标题：「切换复选框状态」（Ctrl+L）、「在列表和任务间切换」「切换无序列表」「切换有序列表」「切换引用」「设为 N 级标题」按 Obsidian 的改法改写选区经过的每一行，九种行（普通、列表项、任务、已完成的任务、有序项、引用、标题、缩进的项、空行）上的结果和笔记的编辑器逐字相同（见 `tests/columnEditing.test.ts`）。「删除段落」（Ctrl+D）、「上移一行」「下移一行」「缩进列表」「取消缩进列表」也能用。
    - 这些命令用 Obsidian 里给它们设的快捷键：用户改过的用改过的（删掉了就没有），没改过的用 Obsidian 的默认键。Obsidian 的公开接口读不到快捷键，编辑器用未公开的 `app.hotkeyManager`（`getHotkeys` 读用户设的，`getDefaultHotkeys` 读默认的），读不到时退回 Obsidian 的默认键（`obsidianInternals.ts`）。快捷键在编辑器打开时读一次。「切换注释」（Ctrl+/）会插入 `%%`、改变块的结构，编辑器不做；CodeMirror 默认键位里的切换注释也不启用，Ctrl+I 也不再是「选中上层语法」。Obsidian 的其他快捷键仍然到不了编辑器（见下面的 `Scope`）。
    - 自动配对：设置里的「自动配对括号」开着时 `( [ { ' "` 成对出现，「自动配对 Markdown 语法」开着时 `` ` * _ `` 成对出现。规则和 CodeMirror 的 `closeBrackets` 一样：引号一类的符号紧跟在字后面时不配对，左括号紧挨在字前面时不配对，输入右半边时跳过自动补上的那个，退格一起删掉；选中文字时输入这些符号会把文字括起来。`~ = $ %` 不配对，但不管这两个设置怎样，选中文字时输入它们都会把文字括起来。编辑器用 Obsidian 在运行时提供的 `@codemirror/autocomplete` 里的 `closeBrackets`，按这两个设置给它配符号；设置用未公开的 `app.vault.getConfig` 读，读不到按开着处理。
    - 编辑器有自己的撤销记录，Ctrl+Z 撤销编辑器里的改动，笔记跟着变；按 CodeMirror 的规则，紧接在 Tab 后的 Shift+Tab 和它合成一步撤销。
  - 链接建议（`linkSuggest.ts`）：Obsidian 的链接建议（`EditorSuggest`）只跟着笔记的编辑器走，在文字栏编辑器里输入 `[[` 不会弹出，编辑器就自己弹一个一样的列表，用 Obsidian 的类（`suggestion-container`、`suggestion-item mod-complex`、`suggestion-title`、`suggestion-note`、`prompt-instructions`），由 Obsidian 的 CSS 画。实测 Obsidian 的列表：输入 `[[`（自动配对成 `[[]]`）后马上列出库里的文件，不选中任何一项，这时回车什么也不做；打字后按模糊匹配排，第一项选中；上下键移动，到头绕回；回车插入链接，光标到 `]]` 后面；Tab 把选中项的名字填进去，列表不关；在名字后输入 `#` 时补全名字，改列这篇笔记的标题（旁边标 H1、H2）；输入 `|` 后不再列文件；Esc 只关列表。附件带扩展名，所在的文件夹写在旁边；列表出现在光标下方 5px。编辑器照这些做：空的时候按修改时间列文件，打字后用 `prepareFuzzySearch` 匹配文件名和别名，用 `renderResults` 标出匹配的字，`#` 后列标题（`[[#` 列本篇的），插入的链接由 `fileManager.generateMarkdownLink` 按用户的链接设置生成（链到本篇的标题时是 `[[#标题]]`）；下面放不下时列表放在光标上方。列表挂在 `body` 下，按下鼠标时 `preventDefault`，焦点留在编辑器里；编辑器关闭时列表一起关。不做的：`^` 块引用和 `[[##` 全库标题。实测：`[[` 列出 33 项、不选中；输入 te 后选中 test1；Esc 关掉列表，编辑器还在输入；回车得到 `[[test1]]`；Tab 得到 `[[text-test`，再输入 `#` 列出它的标题，回车得到 `[[#文字栏测试]]`。
  - 编辑器里的每次改动立刻通过笔记的编辑器写回笔记（写入规则见第 3 节第 8 条），所以笔记自己的撤销记录也能撤销，连续的输入合成一步。
  - 笔记一变，CodeMirror 就会重建块部件，编辑器会跟着消失。输入期间部件用 `updateDOM` 保留原来的元素，条件是这次变化正好是输入的文字：开始注释、图片行和另一栏都没变。别处改动了这个块时，编辑器放弃，部件照常重建。
  - 输入法组字期间不写入：编辑器的 `composing` 或 `compositionStarted` 为真时先不写，组字结束后的下一次更新再写，`compositionend` 之后再补一次。桌面端的 CodeMirror 不用 EditContext（只在 Android 上用），组字事件照常发在编辑器的 `contentDOM` 上。
  - 输入期间插件压入一个没有父级的 `Scope`，Obsidian 的快捷键都不起作用，否则 Ctrl+B 这类编辑器命令会改到笔记的编辑器上；编辑器自己按这些命令的快捷键执行它们（见上面的按键）。Esc 先关链接建议，没有建议时退出（组字时的 Esc 留给输入法取消组字）。焦点离开编辑器、落到页面的别处时（按 Esc、点笔记的其他地方），布局按笔记的内容重新画一遍。窗口失去焦点时 `document.activeElement` 不变，编辑器保持打开，切回来接着输入。
  - 从图片菜单「在左侧/右侧添加文字」打开编辑器时，推迟到菜单关闭之后的下一个任务。Obsidian 的菜单（子菜单也一样）显示后要到下一个任务才压入自己的按键范围（`setTimeout(load, 0)`），隐藏时只弹出已经压入的范围。编辑器如果在这之前压入了自己的范围，菜单的范围随后会叠在上面，回车被它吃掉。实测：指针停在带子菜单的「复制路径」上时点菜单项，三次都出现这种情况；推迟之后三次都正常。
  - 点击时光标放在点到的地方：取点击处之前渲染出来的几个字，在源码里恰好找到一处，就放在它后面，否则放在末尾（用 `caretPositionFromPoint`，Chromium 128 起才有）。
  - 实测（用 DevTools 协议发送真实的点击、文字、输入法组字和按键）：光标落在点到的字后面；A 栏的标题按标题字号显示、`###` 隐藏，内部链接只剩「内部链接」几个字，列表画成圆点；光标移到粗体那一行时 `**` 仍然隐藏，点到粗体上才出现；B 栏的引用有竖线、`>` 透明；输入、换行、Tab、Shift+Tab 都即时写回，撤销在编辑器里生效、笔记跟着变；在列表项后回车接出新的项，在任务后接出 `- [ ] `，空项上再回车结束列表；点复选框写成 `[x]`，焦点和光标不动；Ctrl+B 加粗、再按取消，Ctrl+I 斜体，Ctrl+K 得到 `[二]()` 且光标在括号里；Ctrl+E（Obsidian 切换阅读视图的快捷键）不起作用；组字期间笔记不变，确定后写回；写成代码围栏时框变红、笔记不变，删掉后恢复；Esc 和点击别处都会退出，重画后标题、粗体、列表、复选框都在；「在右侧添加文字」先只显示空编辑器，输入后才写入，回车正常；窗口最小化时编辑器收到 `blur`，但仍是 `activeElement`，窗口恢复后接着输入能写回；Obsidian 的按键范围栈里没有留下插件的范围；控制台没有错误。后来加的也这样测过：把加粗改到 Alt+B、删除线设成 Alt+S 后，Ctrl+B 不起作用，Alt+B 给光标所在的词加粗，Alt+S 给选中的词加删除线；Ctrl+L 按两次得到 `- [ ] ` 和 `- [x] `；Ctrl+D 删掉一行；引用行 Tab 得到 `> \t`，Shift+Tab 还原；`(` 配成 `()`，退格一起删掉；链接建议如上；折行的列表项和引用对齐到文字；公式和 40px 宽的图片画出来，点公式后光标进到 `$` 后面、焦点不动；按 Esc 后画出来的文字栏里公式、图片和两个链接都在；快捷键设置和笔记都恢复原样。
- **阅读视图的分段**：块内的文字和图片行按 Markdown 的规则分成几段（相邻的行合成一段，空行、标题、列表、引用各自成段）。有文字栏的块和文字块整个画在开始注释那一段里（这一段只有注释，本来什么也不显示），块内的段清空，高度为 0。原来画在块内第一行所在的段里，但那一段的类型由文字决定，Obsidian 会按类型另作处理（2026-09-17 实测）：第一行是标题时，Obsidian 为了折叠箭头重画了这一段，布局被冲掉；第一行是表格时，这一段带行内样式 `overflow-x: auto`，成了独立的格式化上下文，会把浮动关在里面，在另一个浮动旁边还会缩窄，布局的百分比宽度跟着变小（46% 只剩 205px）。文字变了时 Obsidian 只重绘文字所在的段，画着布局的那一段不会更新。插件因此记下每篇笔记里画出来的布局依据的内容：所有块的注释行，以及每个有文字栏的块的全部行。只有真正画布局时才更新这份记录，清空的段不更新；`changed` 事件里有一项和记录不同，就重绘阅读视图。实测：在实时预览里改 B 右栏里单独成段的引用，阅读视图随即显示新文字，而且只出现一次；清空的段也更新记录时，阅读视图一直显示旧文字。
- **部件高度**：块部件的 `estimatedHeight` 原来是 -1，CodeMirror 按源码行数估计没画出来的块。两栏文字块一个就有一千多像素，按行数只算几百，整篇的高度表偏小，滚动时跳动；更糟的是块的内容一变（在里面输入一个字），它的高度就回到估计值，视口被重新计算到别处，正在输入的块被移出视图、销毁（实测：块高 1537px 被估成 1161px，视口从第 118–147 行跳到第 4–40 行）。插件因此记下每个块部件画出来的高度（`ResizeObserver`），按块的原文和“笔记 + 开始行”各记一份，作为 `estimatedHeight`；输入时原文变了，按开始行仍能取到。
- **部件的 DOM 复用**：CodeMirror 重建部件时（`findWidget`），会把旧元素依次交给其他块的新部件试 `updateDOM`。文字栏编辑期间，这个元素可能先被别的块的部件试到；这时只返回 `false`，不能结束编辑，编辑只在元素真正销毁时（`destroy`）结束。
- **段信息里的全文**：阅读视图的后处理器用 `getSectionInfo(el).text` 取整篇笔记的文字，但有些段（实测包括公式段）拿到的是空字符串，行号照常。插件拿到空文字时，改用显示这篇笔记的视图的 `getViewData()`（`src/view/noteText.ts`），仍然取不到就不处理这一段。否则这一段会被当成没有布局块、没有标签的笔记处理：公式不编号，带 `\label` 的公式由 Obsidian 原样交给 MathJax 而报错。
- **插件启用前画好的阅读视图**：插件停用、更新或重新加载时，已经打开的阅读视图按普通 Markdown 画过的段会一直沿用，布局、编号都不出现，直到这些段的文字改变。插件因此在布局就绪（`onLayoutReady`）后让已打开的阅读视图整体重画一次（实测：重载插件后，阅读视图的布局从 0 个恢复）。
- **两栏里的分页**：文字块分栏时，标题不和下文分开（`break-after: avoid`），图、表、公式、代码、标注框和图注不拆到两栏（`break-inside: avoid`）；只有一张图片的段落标为图（`vml-figure`），图注前后紧挨着的图、表、公式不和图注分到两栏（`vml-keep-with-next`）。标记在渲染完成后加，不用 `:has()`。实测：原来图 2 在左栏底部、图注在右栏顶部，改后在同一栏，阅读视图和实时预览一致。
- **MathJax 的加载**：Obsidian 启动后，直到有笔记需要时才加载 MathJax。在那之前调用 `renderMath` 会抛出 `MathJax is not defined`，抛在部件的 `toDOM` 里时整篇笔记打不开（实测：重启后打开有编号公式的笔记，标签页停在空白）。插件画公式前先 `loadMathJax()`（`src/view/math.ts`）。
- **分栏**：文字块分栏用 CSS 的 `column-count`，阅读视图和实时预览一样。进入编辑时编辑器是一栏（CodeMirror 量不了分栏里的文字），退出后恢复分栏。点击定位光标时，画出来的文字和源码都去掉空白再比对（原来只去掉了画出来那边的，英文正文几乎总是对不上，光标落到末尾），线索从 32 个字符开始试，依次缩短。
- **文字块**（2026-09-17，测试库的 `text-block-test.md`）：实时预览里靠右浮动的文字块宽 40%，旁边的正文绕排；不环绕、宽 60% 的块靠左，只有右边缘一个改宽度的手柄。右键文字块（插件在布局上接下 `contextmenu`，文字栏编辑器里不接）弹出「不环绕文字」「文字块靠左/靠右，正文环绕」「取消文字块，保留文字」，选靠左后只改开始注释，宽度 0.6 保留。用 DevTools 协议真实点击文字、输入、回车接出列表项，笔记即时写回、框不变红，Esc 退出后按新文字重画。选中两行正文执行命令，得到包住这两行的文字块，光标离开后渲染。阅读视图里文字块整块画在第一段，其余段清空，浮动和替身照常；以列表结尾、没有空行时列表被读进了块外（见 1.1），加空行后正常。块紧跟在段落中间（`段首甲` 下一行是开始注释）、引用结尾紧挨结束注释，阅读视图都分段正常。控制台没有错误。
- **高度表**：有文字栏的块和普通布局块一样，是按实际高度测量的块级部件。实测显示前后、显示源码时，高度表都零偏差。
