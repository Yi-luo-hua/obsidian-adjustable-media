## 1. 实际改造

| 原有冲突来源 | 当前行为 |
| --- | --- |
| 多阅读窗格按文件路径共用绘制记录 | 每个 MarkdownView 独立持有精确快照、desired／host／rendered／measured 和源范围 coverage。重绘请求不推进安装或测量版本；实际 DOM 安装、宿主计算、资源及异步 Markdown 条件参与确认。coverage 只描述观察到的范围。 |
| 固定五次重试后丢掉延后宿主更新 | 发起编辑器的 editor-change 通知相应阅读窗格；未匹配 getViewData 时保持 pending，由该窗格自己的计时器及宿主事件继续核对。新版本替换旧任务，切换／关闭／重载释放观察器、计时器与状态。 |
| 索引事件可能回退到旧内容 | metadata 是核对入口；重新读实际文件，并以事件代数拒绝过期读回。当前源缓冲和文件不一致时不以磁盘覆盖其待协调内容。同步层没有 setViewData 写入，不合并或覆盖其他源缓冲。 |
| 空 section text 取同路径首窗格 | noteText 通过 section DOM／所属渲染器找自己的阅读窗格；无法确认来源就暂不安装布局。初次处理的 detached section 可在插入后确认来源。编号适配使用相同取源入口。 |
| 高度估计缺少环境维度 | 部件高度缓存归属单个缓冲／窗格，键含块实例、内容版本、环境 epoch、实际容器／字体配置、编号、skip 与呈现模式。相同实例的内容更新只在同一环境复用最近尺寸；副本、不同宽度、源码预览不共用记录。 |
| 旧微任务可应用过期几何 | WrapGuard 的 read／write 带文档对象、环境、视口及任务序号。异步微任务再次核对；窗格关闭、源码或视口变化后旧结果不 dispatch。源视图缺少上游浮动的当前尺寸时保持测量未完成。 |
| 字体与主题变化后离屏浮动尺寸仍有效 | 窗格自己的 ownerDocument／window 观察宽度、主题、字体和资源。环境变化清空相应高度／浮动尺寸及旧 gap；纯滚动保留有效内容尺寸。阅读浮动的 detached 尺寸也失效。 |

新增纯模块是 `viewProjection.ts`，环境观察集中在 `viewEnvironment.ts`。阅读后处理源范围使用预计算行偏移，避免每处理一个段落重新扫描之前的所有行。未替换 floatOrder、placement 的兼容关系解释，也未修改原有补偿文件。

## 2. 定向验证

Node 24 下 `npm run check` 的类型检查、官方 lint 与 **222 项测试全部通过**；`npm run build` 通过。最终生产构建 SHA-256 为 `2f50a378e82636f744d9aae00eb7dc227378be5ab90c3bf67c336bded804f16d`，以下五份宿主记录均核对相同加载哈希。宿主为 Obsidian 1.13.7，库为 `vml-test-vault`。

- [双窗关系记录](probes/p2-host.json)：块间空行变正文后，两阅读窗格各重绘一次，在编辑事件后约 154／164ms 发起，早于约 2 秒后的保存和索引事件。未知 V3 单块移除仍保留原文。
- [窗格与延迟记录](probes/p2-sync.json)：受控 720px／397px 容器中，65% 宽的文字块分别约 468px／258px，高度约 286.13px／526.06px；两种视图在各自相同宽度下吻合。第二阅读窗格的 getViewData 注入旧源报告至 950ms，期间重绘为 `[1,0]`；解除后为 `[1,1]`。这验证延后宿主接口，不声称复现真实宿主内部延迟机制。
- 同一记录中，注入另一源窗格的分歧读回及旧 metadata，setViewData 调用为零，阅读窗格未回退。撤销恢复旧文本、四窗格 rename 正常；稳定后 2.1 秒新增重绘为 `[0,0]`，被观察源窗格内部 effect 为 0。真实独立未保存缓冲矩阵仍待验收。
- [命令回归](probes/p2-commands.json) 和 [重复实例写入回归](probes/p2-instance-write.json)：继承 P1 的未知格式零写入、普通操作一步事务／撤销及第二个重复实例正确定位结果；既有笔记哈希不变。该菜单探针采用程序化事件与 DOM 点击，没有代替真实指针拖动。
- [正常窗格表面记录](probes/p2-surface.json)：约 1014px 的实际窗格中，文字块宽约 609.96px、高约 166.16px，两种模式一致；左右浮动各宽约 375.36px、高约 46.20px。已检查 [阅读截图](probes/p2-preview.png) 和 [实时预览截图](probes/p2-source.png)，没有缺失栏内文字。两种模式的正文间距和顶端位置仍有差异，本批没有将其误报为像素一致。
