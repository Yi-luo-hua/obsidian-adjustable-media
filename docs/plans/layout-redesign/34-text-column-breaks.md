## 目的与现状

原有纯文字布局块用 `cols` 和 CSS `column-count` 自动分栏，内容连续流动并尽量平衡各栏高度。0.7.3 增加手动内容边界，让各栏承载自己的内容、允许长短不同，避免主题或段落被自动分到另一栏；没有手动标记时继续自动分栏。

本功能归入「独立功能」，区别于 W06 的多个布局块并列成组。它处理一个文字块内部的内容分栏，不要求先完成移动端适配、W02–W04 最终规划器或 W06 新组格式。

## 确定用法

确定标记为独占一行、顶格书写的 `+++`，表示「结束当前栏，从下一栏继续」。不需要为每一栏成对添加开始／结束标记，最后一栏随布局块结束。

```markdown
<!-- vml {"v":2,"type":"text"} -->
## 第一栏

这里可以只写一小段。

+++

## 第二栏

这里可以写更长的说明。

- 第一项
- 第二项

<!-- /vml -->
```

上述示例表达两栏并排、顶部对齐、宽度相同，第一栏可以比第二栏短。标记本身不显示成正文或横线；普通 `---` 仍是 Markdown 分隔线，不占用它作为分栏语法。

## 首版范围与语义

- **没有标记**：保留既有 `cols` 自动分栏行为，旧笔记无需修改。
- **有有效标记**：按标记切成独立栏，栏数由分段数决定，优先于 `cols`；不因为渲染而自动改写开始注释。删除最后一个标记后恢复按 `cols` 自动排版。
- 每栏内容只在自己的栏内换行，不流入其他栏；框高由最高栏决定，短栏下方自然留白。首版控制的是内容边界，暂不增加逐栏高度或宽度设置。
- 首版沿用最多四栏的范围；首尾或连续标记允许表达空栏。超过范围的手写内容须保留，提示并回退到原有自动排版，不截断、删除或自动重写内容。
- 只在文字布局块的正文中识别专用结构标记；显式 `type: text` 的栏内图片仍属于文字内容。普通媒体布局块、块外正文、围栏／缩进代码、公式、引用／列表内部及其他注释里的同样文字，不作为分栏标记。
- `+++` 仅在文字块的顶层正文识别，允许行尾空白，不接受行首缩进、符号间空格或四个以上加号。列表或引用之后用空行结束嵌套正文，再写标记。已有代码、公式和注释保护保持有效。
- 标记之外的 Markdown、空行和嵌入原文保持不变；旧版本和未安装插件时按原有 Markdown 顺序显示，分栏效果作为降级差异说明，`+++` 显示为普通文字。实现前确认旧版本编辑／写回会保留标记，不把它当作新的布局块边界。

## 编辑与共用实现

提供「插入分栏标记」源码命令，在当前文字块的合适正文位置插入标记，支持一步撤销，不设默认快捷键。源码里可以直接手写或移动标记；文字栏编辑器中直接输入 `+++`，经过当前块的精确读回与写回规则。按用户 2026-10-10 的反馈，移除文字栏编辑器里的插入按钮。

首版沿用当前文字块的单栏编辑器，编辑时能辨认和修改分栏标记，退出编辑恢复手动分栏。各栏原位独立编辑可另作后续增量，不以重写整套编辑器为本功能前置。

分段识别、源范围和栏数规则写成共用纯模块；实时预览、阅读视图及 PDF 使用相同分段结果与渲染入口。建议将每段渲染为独立容器并排排版，而不是只插一个 CSS 强制换栏，避免自动平衡或容器变窄改变内容归属。具体 DOM／CSS 和 PDF 跨页行为由短原型确认。

桌面和移动端共用解析与渲染；窄窗格的呈现策略在实现时明确，不能静默变更分栏标记或栏目顺序。不为 Android 手机／平板、iPhone／iPad复制功能代码。

验证限于本功能相关范围：

1. 自动分栏旧笔记不变；手动两栏／四栏、空栏及长短悬殊内容按指定边界显示，改变块宽不跨栏流动。
2. 代码、公式、嵌套 Markdown 和普通分隔线不误识别；标题、列表、表格及栏内图片的内容保留。
3. 插入／删除标记、直接文字编辑及一步撤销／重做正确，目标外文本与嵌入原文不变。
4. 一台方便使用的代表设备上验证相关交互，并定向检查实时预览、阅读和一份 PDF 的分栏归属；同宽同字体比较排版，跨页规则明确记录。

代码改动运行 `npm run check`。普通增量不追加全量移动设备矩阵；平台专属问题在对应平台复测。首版实际支持范围与未测范围简短记录即可。
