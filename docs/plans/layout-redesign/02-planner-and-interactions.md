# 02 布局规划与拖动

状态：规划。前置：[模型与不变量](01-model-and-decisions.md)。

## 1. 接口和结果状态

建议将现有 `Placement` 分解成操作意图、候选文档和经过约束计算的计划。共享核心保持纯模块，遵循 `.ts` 相对导入、无 Obsidian 值导入与可擦除 TypeScript 的项目规则。

```ts
// 接口草案，不是已实现 API。
type PlanState = "measuring" | "ready" | "blocked";

interface PlanStamp {
  snapshotId: string;
  originViewId: string;
  documentRevision: number;
  environmentEpoch: number;
  viewportRevision: number;
  gestureSequence: number;
}

interface ResolvedLayoutPlan {
  stamp: PlanStamp;
  state: PlanState;
  resolvedTargets: readonly ResolvedTarget[];
  affectedBlocks: readonly BlockRef[];
  candidateSnapshot: DocumentSnapshot;
  measurementsNeeded: readonly MeasurementRequest[];
  readSet: readonly SourceAssertion[];
  sourceEdits: readonly BlockEdit[];
  reason?: PlacementReason;
}
```

`measuring` 展示测量中的候选，不能伪装成最终有效落点；`blocked` 使用明确原因，例如无合法 Markdown 边界、写入权限不足或不可实现的组关系。正常的宽度冲突由规则求出下移／换行位置，通常无需直接拒绝。

SourceAssertion 是对相关块、关系间隔或目标边界的精确原文／上下文断言，不代表写入。snapshotId 绑定实际内容来源，避免同文件两个分歧缓冲的相同数字版本被混用。viewportRevision 只标记屏幕坐标与当前呈现范围，不进入内容尺寸缓存。

核心候选函数接受当前快照、DropIntent、环境和有效测量结果；相同输入生成相同候选结构。真实文字尺寸来自测量提供者，函数不自行读取 DOM。

## 2. 规划步骤

1. **定位来源**：以发起窗格的当前实例解析目标；保留源文本和手势版本。
2. **虚拟编辑**：在内存里计算移除、原位改设置或组成员关系变化，产生候选快照。源移除后再确定目标边界，避免旧高度仍计入目标位置。
3. **找全依赖**：收集源范围和目标范围内相关浮动，以及仍伸入这里的前置同侧／异侧浮动；必要时向前扩展到可信锚点、向后扩展到影响确实结束。
4. **求解约束**：确定合法源顺序、组列宽、正文余宽、浮动堆叠及实际矩形。
5. **测量候选**：补充被改变宽度的文字／媒体和正文尺寸。测量状态由 `measuring` 转为 `ready` 需要同一版本的布局完成证明。
6. **生成并读回源码修改**：生成带原文锚点的 BlockEdit 和独立 readSet；合并同目标修改，校验最终范围不交叠。在内存应用这些实际 edits 并重新解析候选，再按正常打开路径验证布局意图及几何。设置取整、删省略字段和空行规则改变结果时，返回求解／测量，不能直接沿用此前矩形。
7. **呈现最终计划**：显示这份可读回源码的实际位置、吸附原因和需要变化的邻块。只有源码往返与同版本测量完成才标 ready，松手按下述结束规则经 `writeBack.ts` 一次提交。

P0 比较两种候选测量方式：保留真实宿主结构的受限副本，或按宿主适配器提供的已测段落和浮动尺寸做前向规划。独立 HTML、MarkdownRenderer 副本均不能自动证明与 CodeMirror 排版相同；必须用真实 Obsidian 的提交结果校验候选副本，确定支持范围。

P0a 必须包含关闭重开和插件重载：V2 候选最终只能依赖存储的源位置、wrap、skip 等现有字段还原。仅内存锚点能表达而源码不能表达的位置应换合法落点或 blocked；不能只在发起窗格临时实施另一套正文余宽策略。

## 3. 碰撞与稳定性规则

| 情况 | 首选规则 | 预览应展示 |
| --- | --- | --- |
| 同侧矩形在纵向相交 | 当前操作对象吸附到合法顺序与同侧底边之后；需要跨过多个对象时求整个相关集合 | 最终顶端与受影响对象 |
| 异侧能够放下 | 保留双方相对于正文锚点的意图，扣除实际外边距 | 两侧矩形及正文通道 |
| 异侧放不下／正文通道过窄 | 首选下降当前操作对象至解除冲突的最早合法位置；不静默缩小其他块 | 下移后的矩形和原因 |
| 块移出旧浮动集合 | 将仍留在原处的块映射到其正文锚点，重新解析旧集合 | 原集合变化与新落点 |
| 取消环绕／换侧／调整宽度 | 与整块拖动使用同一关系规划入口 | 菜单操作后的可实现结果 |
| 目标在文末、没有可环绕正文 | 落为独立块；只有存在实际正文锚点时才给环绕落点 | 段间插入线 |
| V2 偏移达到范围上限 | 吸附到其他合法正文锚点，或说明现有格式不可表达该位置 | 可写的替代落点／不可放置原因 |
| 并列组横向空间不足 | 按组的响应式策略换行／堆叠，不自动转换为浮动 | 最终组列数和成员顺序 |

异侧正文通道建议使用 `max(正文行高 × 6, 120px)` 作为 P0 的待校准默认阈值，不作为现有 V2 打开时的强制规则，也不在证明前宣称对所有字体合适。计算余宽须计入对象实际 border box、外边距和文字可用宽度。

“保留邻块位置”是保留相对于正文锚点的意图。移动正常占高的块时，文档流自然变化是合法的；保持绝对屏幕像素不是不变量。若约束导致邻块必须变动，要由计划明示，不能在松手后的测量补偿中偷偷修改笔记。

## 4. 指针交互语义

- 块移动仍从块手柄开始；媒体内部移动和组内调整继续使用各自手柄／命中区域，避免同一次手势跨层抢占。
- 纵向整块移动默认保持当前浮动方式。左右位置的改变需要进入稳定的侧边落点区域；区域边界采用滞回，避免在三等分边界附近反复切换模式。
- 组内插入、段间插入和正文环绕用不同的标记形状与标签。当前的媒体行 drop band 不承担组内落点判断。
- 指针在组内时优先产生组槽位候选；只有进入组外明确的段落／侧边区域才产生移出组候选。组内拖出只有一个写入动作。
- 手势记录指针相对被抓手柄的位置，使预览表示块实际顶端；不将指针位置直接当作矩形顶端。
- 移动事件合并到每帧的最新候选。纯滚动更新 viewportRevision 和命中坐标，复用有效尺寸；宽度、样式、资源及实际排版状态变化才更新 environmentEpoch。旧测量不能覆盖新的候选。
- Esc／pointercancel／丢失捕获、切换文件／模式或实例销毁结束手势并清理预览；未发生提交时没有笔记修改。

“保持模式”和滞回是推荐的交互调整，P3 必须用真实鼠标验证用户仍能方便地把块浮到左右。界面文案在 `messages.ts` 同时提供中英文。

### 松手的确定结束规则

pointerup 先吸收释放位置和未处理的最后一次 pointermove，确定最终 gestureSequence；仅落点意图或其坐标依据确实变化时更新序号，同一有效意图可复用已有 ready。不能提交上一帧的不同落点。最终候选已有 ready 且 stamp 有效时提交；仍 measuring、blocked 或已过期时结束手势、零写入并说明原因。首版不在松手后等待资源完成再偷偷提交。取消会失效该手势的全部异步回调；菜单确认遇到未完成计划同样不写入，由下一次明确操作重新规划。

## 5. 写入和撤销

所有关系改变收束到一个 `planLayoutOperation` 入口，再转换为 BlockEdit 和 readSet。宽度、环绕菜单调用该入口；纯内部媒体行调整可以复用现有内容模型，但须先通过格式／组上下文的可写判断，通知布局依赖失效。移除最后一个媒体、拆出媒体、解除注释和合并块可能改变成员存在性，必须作为关系操作处理。

写入前校验发起视图仍属于目标文件、仍可编辑，stamp 与当前快照／环境／最终手势匹配，并核对 readSet 和所有写入目标的完整原文及合法 Markdown 边界。测量导致的临时 DOM 变化不是写入授权。

现有 BlockEdit／resolveEdits 只核对对应写入的 anchor，不能独立表示“只改 owner，但校验全部成员”。P1 定义只读断言契约，P3 在 writeBack 集中接入：编辑器中检查与 dispatch 保持同一同步调用，无中间 await；文件写入在 vault.process 回调内针对实际 data 检查再应用。不要伪造重写未变成员的空操作来充当校验，也不要在异步读取之前核对完就认为可提交。

源码修改只允许：改目标 opener、原样搬运目标块、更新属于本次操作的组成员关系。普通正文锚点不写 ID，非目标空行与换行符不规范化。合法移除／插入间距沿用现有 DESIGN 的有限规则。

未知格式或破损组的可写判断覆盖手柄、菜单、命令、输入转换和批处理；不能只靠渲染时隐藏编辑手柄。R1 先补齐当前移除注释命令的未知版本绕过，后续组功能依赖该统一入口。新接入的命令不绕过 writeBack 直接调用 applyLineChange／applyEditsToEditor。

沿用 `applyEditsToView` 的一次事务、`input.layout`、`isolateHistory` 与现有滚动快照逻辑。撤销／重做恢复成员关系和目标设置，由重解析生成新运行期快照；不要维护另一套独立的关系撤销栈。

手势期间文档改变时，首版继续中止该手势并提示，避免扩大到并发编辑重基。用户下一次操作会使用新快照重新规划。无需增加隐藏自动重试写入。

## 6. 模块落点与退出条件

| 当前模块 | 调整方向 |
| --- | --- |
| `floatOrder.ts` | 逐步成为旧 V2 意图解释器，不再宣称单个 skip 是最终真实矩形 |
| `placement.ts` | 保留合法边界与原文编辑规划；排序和多块关系由共享规划处理 |
| `geometry.ts` | 保留纯命中／吸附计算，将候选坐标与最终布局分开 |
| `blockDrag.ts` | 消费共享计划，不自行绘制未经最终约束计算的落点 |
| `interactions.ts` | 改环绕／宽度时通过同一布局操作入口 |
| `edits.ts`、`writeBack.ts` | 保留原文校验、单事务和唯一写入边界，支持经过合并的多目标 edits |

P3 退出条件：多块跨越、源移除、左右宽度冲突、偏移上限、换侧和菜单操作通过 [验收用例](05-delivery-and-validation.md)；真实 Obsidian 中已标为 ready 的预览与提交后位置在规定容差内一致，未提交操作零写入。

## 8. 当前阶段与完整预览

W02 原型进入条件已具备，W03 仅完成纯约束基础；这里的完整 ResolvedLayoutPlan 与正式入口仍待实现。候选必须从最终 edits 生成源码、重新读回并按同一 context 测量；测量结束不自动补交 measuring 时已松手的操作。完整预览包括移动块、受影响的其他块及正文换行／环绕，不能平移旧几何冒充结果。

默认开启、可关闭的“拖动布局块动画效果”按 [35](35-block-drag-animation-preview.md) 实现，动画层不写笔记、不给未测计划授予 ready，关闭保留同一静态有效预览。
