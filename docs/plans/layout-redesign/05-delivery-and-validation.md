## 4. 自动检查与真实验收的分工

### 纯逻辑与事务测试

重点测试性质：原文守恒、写入范围互不交叠、只读依赖断言、全有或全无、稳定身份、依赖覆盖、过期计划拒绝、源码往返、撤销恢复关系。对 2–4 对象排列和宽度边界做参数化案例即可，不为每个实现分支写镜像测试。

用 memoryEditor 检查事务与精确源文本。旧探针用于说明基线缺陷，修复后不能仍要求保留错误结果；将相应场景转成正确语义的回归测试。纯 skip 数值不能代替真实矩形断言。

### Obsidian 宿主验收

测试仅在 `vml-test-vault`。会修改笔记的脚本先备份，结束恢复并核对 SHA-256；临时快捷键和热键文件恢复核对。先确认后台测量没有被隐藏页面节流，再测布局。

加载构建的哈希、插件版本与环境写入记录。真实拖动、点击、快捷键和中文组字使用项目 AGENTS 所述 DevTools 输入协议，记录 debugger 是否由脚本 attach，结束恢复焦点仿真。源码相同不证明实际加载构建相同。

快照记录建议包含：场景 ID、原始源文本或专用 fixture、文档／环境／手势版本、宿主模式、宽度／行高／字体、资源状态、候选与提交矩形、受影响成员、事务数、稳定轮数、延迟与错误。截图是必要的视觉补充，不替代几何和源文校验。

### 首轮量化标准

| 维度 | 起始验收标准 | 说明 |
| --- | --- | --- |
| 数据 | 媒体嵌入、栏内原文和非目标字节零意外变化 | 硬门槛，不因性能调整放宽 |
| 原子性 | 改变源码的成功手势一个布局事务；中止、不匹配或等价落回原位零事务 | 栏内逐次输入按既有规则单独计算 |
| 预览 | 相同环境且资源稳定时，ready 预览与提交后各边坐标差不超过 2 CSS px | P0 验证测量精度；不同宽度不作逐像素比较 |
| 同步 | 宿主内容匹配且资源可测后，所有目标窗格进入相应版本，初始目标 500ms 内 | 性能目标需 P0 校准；超过仍保持 pending，不把超时当成成功 |
| 收敛 | 无新输入时停止新投影／补偿；稳定后连续 2 秒无重复布局 effect | 测量轮数预算由 P0 记录的有效路径确定 |
| 滚动 | 无布局意图／资源变化时，同一正文锚点的额外位移不超过 2 CSS px | 继承现有滚动测量方法，标注首次／快速路径 |
| 响应 | 200 块／1 万行基线下，单次候选纯计算 p95 起始目标 ≤8ms，单帧测量／应用 ≤16ms | 待 P0 记录硬件与样例后冻结；不是当前已测结果 |

若起始性能目标需修改，要记录实测瓶颈与新门槛再更新本文件；不得只删除失败记录。源文守恒、原子性、版本正确性和 ready 的真实性不是可降级的性能指标。

## 5. 主要风险与处理出口

| 风险 | 发现阶段 | 处理出口 |
| --- | --- | --- |
| 原生正文重排无法被候选测量准确复现 | P0 | 修订测量／可支持落点，不上线虚假的 ready 预览 |
| 源顺序与 CSS clear 限制可表达位置 | P0/P3 | 明确定义吸附／下移，显示原因；不升级成全篇自由画布 |
| 整组替换影响选择或中文组字 | P0/P5 | 调整部件与编辑生命周期；必要时先交付只读呈现及源码编辑 |
| 宿主内部阅读 API 变化 | P0/P2 | 集中适配并记录支持范围，未完成投影保持待处理 |
| 新组只能旧版默认显示 | P4 | 明确降级预期，验证禁止旧版误写；不承诺旧版完整样式 |
| 当前未知版本被移除注释命令改写 | P0b/P1 | 先补齐保护；仅向验证过的构建声明安全降级 |
| 格式模块先合入但呈现尚未验收 | P4/P5 | 不开放创建／转换入口，不先生成用户 V3 笔记 |
| 依赖范围太大造成长笔记延迟 | P1/P6 | 正确性建立后缩小失效范围、缓存有效测量，保留完整基线对照 |

估算先以工作包大小和门槛判断，P0 后再给工时；不能在宿主测量方式尚未证明时承诺固定完成日期。原路线先完成相应 P0 门槛，不先批量改格式或大范围替换渲染器；当前实际执行顺序以 [09 任务队列](09-progress-and-next-steps.md) 为准。
