# 04 并列组与格式

状态：格式候选，未成为当前存储规范。当前 V2 仍以 [DESIGN.md](../../DESIGN.md) 为准。

## 1. 首版功能边界

并列组用于独立布局块之间的明确并列，首版支持连续成员、单层、正常文档流中的 2–4 个成员。成员数量是首版交互和验收范围，不作为永久格式上限；解析未知数量时不擅自截断内容。

组内使用 Grid，组高由最高列或响应式堆叠后的总高确定。列权重属于组；成员内部媒体行、文字栏和文字分栏仍使用各自模型。普通正文不属于组，不能夹在成员之间被自动收进组。

首版不开放组嵌套、成员向组外浮动或整组对正文浮动。左右浮动夹正文继续由 V2 浮动集合处理。组整体浮动需另行验证，不能把一次完整占高的组排版误当成跨段环绕解法。

## 2. 格式方案的兼容证据

2026-09-30 使用当前解析与编辑函数得到：

| 候选 | 当前 V2 解析器行为 | 结论 |
| --- | --- | --- |
| V2 opener 加 id、groupId、groupLayout | 可显示、isEditable=true；现有编辑仍可执行 | 未知字段保留不能阻止不理解组关系的旧版本误写 |
| 普通块 opener 改为 v:3 | 可按默认模型显示、isEditable=false，报告不支持版本；模型编辑返回 null | 只证明模型编辑拒绝，命令写入隔离已存在反例 |
| V3 外层 wrapper 包住普通 V2 块 | 当前扫描器识别内部 V2 并允许编辑 | 新外层注释不能保护内部成员，也引入嵌套语法 |

表中 V3 只证明普通模型编辑被拒绝。二次核验已确认当前基线的 `planUnwrap`、单块移除注释命令和批量移除注释没有 isEditable 检查，仍能删除未知 V3 的组信息。故当前 0.6.1 基线不能认定为安全降级目标，V3 不是完整的旧版写入隔离。复现见 [基线探针](../../research/LAYOUT_PROBES.md)。

推荐先在 R1 补齐所有入口的未知版本保护，再将经过旧构建实测的保护版本列为 R2 支持的降级目标。R1 修复不能改变已经安装的 0.6.1 及更早版本；这些版本只记录已知破坏路径，不承诺其只读安全。若产品要求包含它们，P0b／P4 必须更换兼容策略，不能靠版本号声明满足。版本与字段仍为候选，接受条件见 [ADR 0002](../../adr/0002-versioned-flat-groups.md)。

## 3. 首选候选：平坦的版本化成员

沿用每个块自己的开始／结束注释，不增加包住多个块的外层注释。每个参与组的块升级为 V3，具有唯一成员 ID 和 groupId；第一个源码成员持有组设置。成员之间只允许空行。

以下是草案，字段命名和版本号须在 P4 的兼容门槛通过后冻结：

```markdown
<!-- vml {"v":3,"id":"block-a","groupId":"group-1","groupLayout":{"columns":[{"id":"block-a","weight":1},{"id":"block-b","weight":1.4}],"gapEm":1,"align":"top","responsive":"stack"}} -->
![[image-a.png]]
<!-- /vml -->

<!-- vml {"v":3,"id":"block-b","groupId":"group-1"} -->
说明文字仍属于这个块。
<!-- /vml -->
```

`columns` 的成员顺序必须与源码中的连续成员顺序一致。显式成员引用用于校验关系和按 ID 保留列权重，不形成另一套可独立编辑的排序真相。重排会同时原样移动成员块并更新 owner 设置。

一组只有一个 owner，必须是第一个源码成员；成员 ID 唯一、groupId 相同、列引用完整且无重复。普通正文隔开同 groupId 的块、缺少成员、重复 ID、多个 owner 或顺序不一致均为不可编辑关系。插件可显示安全的独立内容并说明关系不完整，不在渲染时自动修复源码。

已知组字段也参与可编辑判定：列权重必须有限且大于 0，间距必须有限且非负，对齐和响应式值必须是已支持值。不认识的附加字段原样保留，但已知字段非法时不猜默认值后重写组关系。

首版组默认占满正文容器。列宽按可用宽度扣除间距后分配。成员的既有 `width` 设置在单元格容器内解释，内部行与文字栏的比例保留；创建组的预览必须呈现这个参照容器变化，不能承诺与独立浮动时一样宽。组列权重和成员内部宽度分别调整，避免一个宽度手柄同时修改两层含义。

响应式 `stack` 按源顺序堆叠。设列权重为 wᵢ、最小可用宽度为 mᵢ、间距总和为 G，横排至少需要 `G + max(mᵢ × Σw / wᵢ)` 宽度；权重不等时只把各列最小宽度相加不足以证明每列够宽。P0c／P5 校准 mᵢ，覆盖中文、长链接、代码、媒体行和内部多栏。Grid 单元格避免自身的自动最小尺寸撑破分配宽度；内容按原模型换行／滚动，不裁掉原文。断点变化不写入列设置。

## 4. 操作与写入范围

| 操作 | 明确目标 | 一次事务中的改动 |
| --- | --- | --- |
| 创建组 | 用户选择的连续可编辑块 | 目标 opener 的版本、ID、组关系；清除成员外部 wrap／skip；内容与块间空行原样保留 |
| 组内重排 | 整个组的关系及被移动成员 | 原样移动成员块；owner 的成员顺序与列权重更新 |
| 改列权重／间距 | owner | 只更新 owner 的组设置 |
| 成员拖出 | 原组与该成员 | 移动成员；更新原组引用；必要时转移 owner；目标位置用统一规划 |
| 成员拖入／跨组移动 | 来源块／原组、目标组 | 原样移动目标块，更新两组关系；新成员的 ID、版本及外部 wrap／skip 处理遵守创建组规则 |
| 整组移动 | 全部组成员及组间空白 | 搬运完整连续范围，保留每个成员原文 |
| 解散组 | 全部成员 | 移除组字段，成为正常文档流的独立块；不自动恢复旧浮动位置 |
| 删除／拆散至单成员 | 剩余成员及旧 owner | 清除失效组关系，成员内容保留 |

创建组本身是用户明确改变布局关系的操作，因此外部 wrap／skip 的清除必须包含在预览和一次可撤销事务中。撤销恢复原有浮动设置和完整原文，不额外保存第二份历史元数据。解散组默认得到正常文档流；用户可继续把成员浮到正文旁边。

owner 移动或退出时，旧 owner 和新 owner 都属于本次目标；必须校验全部成员关系的原文再原子提交。组范围外的正文只作为校验锚点，不进入重写范围。组合操作复用现有 BlockEdit／writeBack，不另开直接 Vault 写入渠道。

只改变 owner 时，其他成员和间隔仍进入 readSet，只校验、不重写。首版超过 4 个成员的拖入候选 blocked；手写更多成员安全显示完整内容但不开放未验收的组编辑。组内调整只改权重时也须确认成员关系未被外部输入改变。

### 现有内部操作的接入边界

V3 不能直接交给当前 V2 解析／序列化链路：findV2Blocks 拒绝未知版本设置，serializeOpener 默认输出 V2，planColumnText 的读回也只用该解析器。P4 提供统一的版本化块解析／序列化和组上下文可写判断，P5 为普通模型操作提供适配，保留版本、ID、关系与未知字段。

特别处理移除最后一个媒体、媒体拖出、解除成员注释、合并块、自动追加媒体与栏内文字读回。当前 planModelEdit 在最后一个媒体消失时可能删除整个成员注释；不能仅通知尺寸失效。成员消失、解包或合并必须同步更新组引用、owner 和单成员解组。破损组成员不通过内部媒体手柄、命令或自动转换绕过整体不可写状态。

创建组只清除本次明确转换的外部浮动意图，保留内部行列设置。含文字栏块的旧 setWrap 直接返回原模型，可能保留原本不起作用的 wrap／skip；V3 格式操作需要显式定义这些字段的处理，不假设调用该函数就已经清除了它们。全部改变由最终源码读回和预览验证。

## 5. 迁移与降级

| 打开方式 | 预期行为 | 发布前验证 |
| --- | --- | --- |
| 新插件打开 V2 | 沿用兼容解释，不生成 ID、不迁移、不写入 | 老笔记完整哈希不变 |
| 新插件打开有效 V3 组 | 按明确关系呈现并编辑 | 双视图、历史和原文保持 |
| 新插件打开破损或未知格式 | 安全呈现内容；关系不可写 | 所有入口不能产生猜测修复 |
| 经验证的 R1 保护构建打开 V3 | 默认独立呈现，丢失组样式；所有插件写入入口拒绝未知版本 | 尚待实现、加载该构建逐入口检查 |
| 当前 0.6.1 工作区基线打开 V3 | 默认显示；已确认移除注释命令可破坏关系 | 不列为安全降级目标 |
| 其他未经逐入口验证的历史构建 | 不推断其保护或默认展示能力 | 记录实际构建行为，不声明安全降级 |
| 没有插件 | 普通 Markdown 内容仍存在；注释隐藏，组样式丢失 | 原生实时预览／阅读展示 |

未知版本“不写入”与“完整保留视觉样式”是不同目标。当前仅有模型编辑拒绝证据，完整写入隔离在命令路径已被反例否定。旧构建验证不得只检查菜单隐藏或 planModelEdit 返回 null。

组解除后保留 V3 成员身份，避免自动反复升降版本。将无组 V3 转回 V2 如有需求，应作为明确命令另行定义可丢失字段与预览，不在普通渲染或解组时隐式进行。

复制操作由插件主动执行时生成新 ID；用户手工复制导致重复 ID 时标记关系冲突，不主动改文件。ID 在单篇文档内用于关联，不用于跳过当前文件、源范围和原文校验。

未知字段与 JSON 转义继续遵守现有约定；不得破坏 `--`、`%%` 或原有嵌入。格式纯模块需覆盖未知版本、手写字段、CRLF、代码／公式／注释上下文、重复成员和部分拷贝。

## 6. 呈现与编辑门槛

实时预览可能把整个连续组替换为一个块部件。P0／P5 必须验证选择进入源码、成员文字栏编辑、中文组字、快捷键路由、源码展开、折叠、撤销及滚动高度。

成员内容编辑继续写回成员自己的行范围，写入前读回完整块；组投影只反映新快照，不接管普通正文编辑。组内／组外／媒体行手势按 [拖动规则](02-planner-and-interactions.md#4-指针交互语义) 划分。

若原生选择或输入法门槛未通过，可先交付只读组呈现及源码编辑，但必须明确缩小该阶段范围，不能称组内直接编辑已完成。P4 只完成格式与原文写回验证，也不能视为 P5 功能已交付。

PDF 是分页环境，不能以屏幕上的完整占高承诺整组永不拆页。P0c／P5 验证跨页文字、超高成员和大于一页的组；首选保留列关系且允许合法分页，宿主不能可靠分页时验证按源顺序堆叠的导出降级。不得截断、溢出纸面或留下无法阅读的巨大空页。该规则冻结前，R2 不宣称导出已支持所有组内容。

P4 可合入解析和纯计划模块，但不向用户注册创建／转换组的入口；直到 P5 对准备交付的呈现与交互范围验收通过后才开放。无需提前生成 V3 笔记等待另一阶段补上呈现。

格式决策记录见 [ADR 0002](../../adr/0002-versioned-flat-groups.md)。
