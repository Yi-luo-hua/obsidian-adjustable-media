# 03 视图同步与测量

状态：规划。前置：[模型](01-model-and-decisions.md)、[规划结果](02-planner-and-interactions.md)。

实施进展：每窗格协调状态、来源回退修正、环境缓存及过期测量保护已接入，定向双窗验证见 [08 实施记录](archive/08-pane-foundation-record.md)。本文其余要求仍按完整 P2／P3 门槛验收，不因基础实现通过而视为全部完成。

## 1. 同步的是内容和意图，测量属于窗格

同一文件的窗格订阅已确认的内容快照和布局关系。宽度、字体、主题、缩放、媒体固有尺寸、源码展开与文字编辑状态属于各窗格的环境，不能随文件路径共享高度。

同宽且环境相同时，实时预览与阅读视图使用同一规划规则并核对布局矩形；异宽窗格保留同一成员顺序、正文锚点及相对意图，允许正常换行和堆叠。同步不要求不同窗格的屏幕坐标相同。

## 2. 内容来源与版本协调

建议新增 `documentSnapshot.ts` 与 `viewCoordinator.ts`，区分以下来源：

| 来源 | 接受条件 | 处理 |
| --- | --- | --- |
| 发起编辑器的布局事务／正文输入 | 事务已应用，读取的是该编辑器的当前内容 | 更新该来源快照，通知同文件视图 |
| 外部文件或 Vault 更新 | 已读取确实变化的文件内容 | 形成外部快照，等待宿主采用该内容 |
| metadataCache.changed | 只是索引更新通知 | 请求核对实际内容；不单凭事件认定已呈现 |
| 阅读窗格内容更新／重新加载 | getViewData 与目标内容匹配 | 允许安装该快照的布局投影 |
| 同文件另一源窗格内容不同 | 尚无法证明宿主已同步 | 保留该窗格自己的内容状态，标记待协调 |

不能简单把“最后收到的事件”当成最新内容：磁盘保存、索引更新和编辑缓冲的到达顺序不同。P0 记录真实事件顺序、内容指纹和来源，确定哪些事件能够确认宿主完成同步。

插件只观察和适配宿主的内容同步，不使用 `setViewData()` 把一个窗格的快照覆盖到另一个有未同步输入的编辑器，也不实现 CRDT 或自行采用最后写入获胜。未保存的缓冲与磁盘不一致时，以发起操作编辑器的精确原文为写入依据；其他窗格在宿主内容匹配后才采用它。无法确认来源顺序时保持 pending，不回退已有投影，不猜测合并。

文件实例、来源分支和 snapshotId 组成内容身份；数字 revision 只在其事件序列内比较。同内容可复用解析，但不能把内容指纹当成事件先后。撤销／重做回到旧文本是一次合法新事件，必须分配新版本，不因“曾显示过这段内容”拒绝同步。分歧缓冲各有 host 状态，只有证明宿主采用同一内容后才合并订阅关系。

阅读 section 必须关联到自己的窗格和内容来源。初始方案曾发现同路径第一窗格回退；当前 `noteText.ts` 已通过 section DOM 所属阅读窗格取源，无法确认时返回空来源。这项基础修复已验收，后续仍须保护每个来源、迟到回调与分歧缓冲。PDF 和嵌入笔记分别处理自身来源，不能冒充当前阅读窗格。

Obsidian 的公开 `editor-change`、`file-open`、`layout-change`、`resize` 和 metadata cache 事件可作为入口，但每个事件的实际覆盖范围需要 P0 实测。当前 API 声明见 [官方 obsidian.d.ts](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)；对阅读呈现完成的内部接口依赖仍集中在 `obsidianInternals.ts`。

## 3. 每窗格确认状态

每个 ViewProjection 保存：

| 字段 | 含义 |
| --- | --- |
| desiredRevision | 此窗格等待采用的内容版本 |
| hostRevision | 已核对宿主当前内容对应的版本 |
| renderedRevision | 布局投影确实安装到宿主后的版本 |
| measuredRevision | 所需范围的有效测量对应的版本 |
| environmentEpoch | 此窗格宽度、样式、媒体及编辑状态的变更序号 |
| viewportRevision | 纯滚动坐标与可见范围序号，更新命中和 coverage，不失效有效内容尺寸 |
| coverage | 已完成呈现／测量的源范围及未完成范围 |
| taskToken | 窗格实例、文件、版本、环境与任务序号组成的回调标记 |

虚拟视图不必一次渲染整篇笔记。因此 renderedRevision 的确认必须附带 coverage，表示当前可见及替身所需范围已完成，不能把一次回调当成整篇完成。测量版本还须带 environmentEpoch。

建议状态顺序：`waitingForHost → projecting → measuring → settled`。新内容到达时合并过期任务；宽度或媒体变化只重置环境相关的测量状态。切换文件、模式、折叠范围或关闭窗格使对应 taskToken 失效。

文件 rename 更新路径索引及所有订阅，已有旧路径任务作废；文件删除、窗格／弹出窗口关闭、插件禁用或重载释放订阅、观察器、计时器、候选副本与对应缓存。测量和调度使用窗格自己的 ownerDocument／window，不能把主窗口环境用于弹出窗口。

调用重绘、创建 renderer 或更新“已绘制记录”都不是成功确认。布局安装完成后读取实际 DOM 和宿主范围，核对任务仍有效，才推进 renderedRevision。旧回调不能覆盖新版本。宿主迟于 500ms 才采用内容仍可被后续事件唤醒；不把固定五次重试当成最终同步协议。

## 4. 依赖失效

布局快照至少包含块间正文拓扑与浮动关系，替换目前仅比较 opener、closer、栏内文字和引用编号的判断。

| 变化 | 必须失效的范围 |
| --- | --- |
| 块内容或宽度改变 | 本块、所属组、受其浮动影响的后续范围 |
| 块间空行改正文、插入／删除块 | 新旧锚点及关系集合，直到影响结束 |
| 换侧、取消环绕、移出旧位置 | 原集合与目标集合 |
| 组成员、列权重、间距改变 | 整组及依赖组占高的后续位置 |
| 字体／主题／窗格宽度改变 | 该窗格的全部相关尺寸；其他窗格不复用结果 |
| 媒体／MathJax 晚加载 | 对应内容尺寸及受影响范围；不改变内容版本 |
| 标题折叠、源码展开、进入栏内编辑 | 对应呈现范围、替身和高度表 |

P1 初版可以对正文拓扑变化失效整个文件的布局关系，再在已有正确性证据下缩小范围。这比建立一套看似增量、实际遗漏依赖的规则更容易验证。每次指针移动不能重新扫描全文；手势开始建立关系索引，后续只计算相关集合。

## 5. 测量键与坐标

测量键建议为：`viewInstance + blockId + contentRevision + environmentEpoch + measurementSpec + renderMode`。measurementSpec 包含本次候选的实际可用宽度、行／分栏配置、组单元格宽度及会影响尺寸的样式参数；这些必须参与匹配，不能只作为日志。原文用于内容校验，不作为实例身份；源行号是当前位置，不作为稳定 ID。

同一窗格中未提交的两个候选宽度不同，即便文档与 environmentEpoch 相同，也不能共用文字高度。纯滚动不改变 measurementSpec；新增覆盖范围按需测量，已有同环境内容尺寸仍可复用。

同内容的两个块使用不同实例记录。移动一个块时可以复用同环境的内容尺寸，但必须重新求解位置；从宽窗格到窄窗格不复用高度。媒体尚未获得固有尺寸时，结果带未完成状态，之后的 load 回调只能更新仍有效的实例。

测量返回文档坐标或明确的锚点相对坐标。视口滚动偏移单独转换，不能把 `getBoundingClientRect().top` 直接存入跨帧文档缓存。组高取真实布局结果，不按成员宽度比推算文字高度。

## 6. 宿主适配与收敛

### 实时预览

保留 CodeMirror 对正文、选择、输入法和滚动的控制。可能改变垂直布局、替换跨行范围的块部件应通过直接 decoration set 提供，例如 StateField；ViewPlugin 可提供与视口有关的行内／替身装饰，但不能违反块装饰限制。

按 `requestMeasure` 的 read／write 顺序批量读取和应用几何结果。避免在 ViewPlugin.update 中同步读取布局，也避免 read 阶段 dispatch。需要更新高度相关状态时只提交数值确实变化的内部 effect，且不触发笔记写入。

以上约束以仓库当前 `node_modules/@codemirror/view/dist/index.d.ts` 的 ViewPlugin.update、requestMeasure 和 EditorView.decorations 声明为依据；实现时核对锁定版本。参考 [CodeMirror 官方 API](https://codemirror.net/docs/ref/#view.EditorView.requestMeasure)。

### 阅读视图与导出

阅读适配器负责段落生命周期、折叠、离屏段落、必要替身和宿主重测。位置规则与浮动结束条件来自共享计划，不在 `readingWrap.ts` 里另造排序规则。

并列组在首版是完整占高的渲染单元，按当前容器宽度排版。跨段浮动仍需要虚拟呈现适配。导出不使用视口裁剪与替身，冻结实际导出来源的快照，再确认相关内容和资源完成；不把发起编辑器的拖动候选或其他窗格的未保存版本混进 PDF。超高组的分页／降级规则见 [格式方案](04-groups-and-format.md#6-呈现与编辑门槛)，须核对真实 PDF。

### 收敛条件

每轮为“读取有效尺寸 → 求解 → 应用有变化的投影 → 必要复测”。同版本、同环境且几何不变时结束。缓存命中、测量状态和应用标记须阻止相同结果反复提交。

P0 记录稳定需要的测量轮数和原因，建立明确的收敛预算。超预算时停止当前循环、记录原因并转为待验证呈现；不能把旧缓存标成 ready，也不能继续无条件微任务补偿。只有新内容、环境或有效资源事件才能重新唤醒。

## 7. 模块与验证出口

| 当前位置 | 实施方向 |
| --- | --- |
| `drawn.ts` | 由完整关系快照参与失效判断；不再仅按局部块指纹判断 |
| `readingView.ts` | 每窗格协调与完成确认；延后加载保留 pending |
| `noteText.ts` | section 无文本时按自身窗格取源；禁止同路径第一窗格回退 |
| `livePreview.ts`、`wrapGuard.ts` | 运行期身份、环境键、明确坐标及版本化测量 |
| `readingWrap.ts`、`wrapProxy.ts` | 消费共享的浮动关系与替身计划 |
| `obsidianInternals.ts` | 集中宿主内部能力探测与受限降级，不向核心渗透 |

P2 的完成证明包含：块间正文变更能唤醒两个阅读窗格；不同宽度不交叉复用尺寸；旧异步回调不能回退版本；稳定后停止测量；不同编辑缓冲不被插件覆盖。详细场景见 [交付与验收](05-delivery-and-validation.md)。

## 8. 已冻结的原型调用方契约

W02 的 Windows 既有 V2 原型门槛已通过，具体 API 与证据在其工作树；正式调用方尚未接入，见 [摘要](archive/branch-validation.md#w02-candidate-prototype)。所有者提供实时 context，推进真实源／资源／样式／呈现代际，在事件中 refresh，卸载时 dispose；状态读取不能替代事件订阅。纯滚动不推进环境代际。

首轮测量候选全部布局和完整正文；基线含保护正文与 EOF 的只读依赖，不制造未变成员写入。有影响结束证明前不缩小相关集合。保留测后销毁副本；冷测、纯计算、回调累计、峰值与长任务分别记录，预算见 [05](05-delivery-and-validation.md#首轮量化标准)。
