P0a 首先核对实际构建与加载文件哈希，复现基础问题并记录事件顺序。Obsidian 1.13.7 中，专用笔记的编辑事件立即出现，保存和 metadata 事件约晚 2 秒，两个阅读窗格在索引事件前已采用新文本。该结果只确认本批数据契约；候选副本、跨宽度测量、延迟宿主与收敛预算仍待验证。P1 基础在已确认的数据契约上实施，P3 的候选可实现性门槛没有被跳过。

## 2. 已实现的基础

| 基础 | 行为与接入 |
| --- | --- |
| 精确快照 | `documentSnapshot.ts` 保存原始文本、文件实例、缓冲来源、快照 ID 和来源内版本。撤销到旧文本也分配新事件版本。 |
| 块与正文身份 | CodeMirror 事务先映射现存实例，再对唯一剩余的原样移动匹配身份。重复块分别保留 ID；外部全文替换无法区分重复实例时重新建立 ID。渲染实例的修改经 `blockIdentity.ts` 绑定当前实例并核对原文，实例消失／变化就取消，不误写占据旧行号的副本。正文边界沿用现有合法落点，不写持久 ID。 |
| 完整关系基础 | 全部浮动进入关系索引；空白相邻集合包含同侧块，集合与旧 skip 解释分开。影响结束未经几何证明就标为未知；EOF 边界不冒充可环绕正文。 |
| 依赖失效 | 有浮动时用完整源文本保守失效。块间空行变正文能触发相关布局重绘。实时预览的部件、高度记录和替身尺寸先按实例区分；环境 epoch 尚属 P2。 |
| 只读断言 | `sourceAssertions.ts` 提供独立 readSet。Editor、CodeMirror、文件路径均在实际应用处核对，不通过重写未变成员充当校验。 |
| 格式入口保护 | `planUnwrap` 对不可编辑块返回 null；批量发现和计数跳过这些块；事务核心拒绝任何与不可编辑块相交的修改。模型、命令、图片菜单、自动转换使用共同写入边界。 |
| 写入与历史 | 命令和转换的 LineChange 转为锚定修改，经 writeBack 提交。来源编辑器仍须属于目标文件；原生 CodeMirror 可用时采用隔离的一步布局事务，空计划不产生事务。自动转换不在切换到另一文件后应用旧位置。 |

这些基础不改变 V2 存储规范，也不生成 V3。关系索引尚未替换 `floatOrder` 的兼容解释或 `blockDrag` 的估算预览。

- `npm run check`：类型检查、lint、217 项测试通过。新增语义检查覆盖重复实例、上方插入、设置修改、移动与撤销／重做、来源分歧、正文依赖、CRLF、只读断言及未知格式原子拒绝。
- `npm run build`：生产构建通过。本批最终宿主验证加载哈希为 `9e29b259d0d17cd8c206d0a19f754a5a0548e8eee942e4faeb799272130d9e28`，与仓库构建一致。
- [P0a 基线宿主记录](../probes/p0a-baseline.json)：两个阅读窗格均采用新文本，但布局重绘次数为 `[0,0]`；未知 V3 单块移除会去掉注释。
- [P1 同一场景记录](../probes/p1-host.json)：两个阅读窗格各重绘一次，右侧布局顶端由约 397.65px 更新为 411.44px；未知 V3 原文保留。容器仅约 71px 宽，该记录证明失效／重绘链路，不证明跨宽度排版或最终拖动几何。
- [P1 真实命令记录](../probes/p1-commands.json)：前文插入及撤销保留运行期身份，撤销产生新版本。未知格式移除／包装／合并零文档事务；普通移除、包装及批量移除各一次事务且可撤销。批量发现临时限定为单个测试 fixture，只计入其中一个可编辑块，未知块原文保留。
- [P1 实例写入记录](../probes/p1-instance-write.json)：先打开第二个重复文字块的菜单，再插入四行，让第一个副本占据第二个块的旧行号。旧菜单仍只修改第二个实例当前的第 10 行 opener，一次写入事务，撤销原样恢复。这是程序化宿主菜单事件／DOM 点击，不是实际指针拖动。
- 命令探针前后核对测试库所有既有 Markdown 文件 SHA-256，原文全部不变。专用临时笔记在结束时移入测试库内部垃圾箱，脚本拒绝覆盖已有同名文件。测试插件三文件以运行前副本恢复并核对哈希；仓库的构建产物保留，但不入库。
- `dev:errors`：验证结束时没有捕获到插件错误。这不代替所有异步资源／主题场景验收。

可复跑的宿主脚本为 [事件与关系探针](../probes/p0a-host.js.txt)、[命令探针](../probes/p1-commands.js.txt) 和 [实例写入探针](../probes/p1-instance-write.js.txt)。仅允许在 `vml-test-vault` 执行，使用 AGENTS 规定的一行文件加载方式；重新验证时须先部署当前构建并核对哈希，不能用已恢复的旧测试插件代替。

## 4. 首轮性能

[基准脚本](../../../../scripts/layout-snapshot-benchmark.mjs) 在仓库根目录用 Node 24 运行。200 块／1 万行、5 次预热和 20 次采样，Ryzen 9 7945HX 的快照构建及身份映射 p95 由约 [30.33ms](../probes/p1-performance-before-index.json) 降到 [12.17ms](../probes/p1-performance.json)。改进来自正文边界映射按偏移建索引，避免每个新边界扫描全部旧边界。

该数字包含源事件解析，不是候选求解或真实一帧耗时，不能据此宣布通过 P3／P6 的性能标准。后续手势复用既有快照，不应在每次指针移动时再做这段工作。
