# 边框高亮选项与手机端适配规划

登记日期：2026-10-08；状态更新：2026-10-09。W08 已本地验收（[14](14-highlight-execution-record.md)），W09 Android 基线、W01 Windows 已列门槛通过；华为 11.5S 已列输入／显示及视频播放／缩放有真机证据，视频原页手指复核通过（[20](20-tablet-acceptance.md)、[24](24-mobile-video-controls-focus.md)）。剩余设备／生命周期矩阵、W02 几何与 W11 统一规划门槛见 [25](25-documentation-and-artifact-cleanup.md)，iOS 按用户要求暂缓。正式 `manifest.json` 仍为 `isDesktopOnly: true`，格式仍 V2，不提前开放正式手机支持。

## 1. 顺序与依赖

建议执行顺序：**W08 边框选项 → W09 手机平台验证 → W01 生命周期 → W10 手机显示与输入 → W02 候选可实现性 → W03 统一规划 → W04 手势接入 → W11 手机触摸操作 → W05 集成验收 → W06 并列组**。

这个顺序是优先级建议；硬依赖如下：

- W08 是可独立交付的小改动，不依赖新规划器。先明确光标／焦点状态，W01 再覆盖它的完整生命周期。
- W09 可在现有 V2 上开始，先发现手机运行时与内部接口差异，作为 W01 和后续规划器的输入；与 W08 无代码依赖。
- W01 完成后开展 W10，处理窄屏、软键盘和文字输入；可以与 W02／W03 的桌面规划工作分别推进。
- W11 依赖 W10、W03／W04，把触摸接到同一操作计划，避免为手机维护另一套落点和写回规则。具体触摸原型可以提前在 W09 验证。
- W05 的桌面 R1 验收仍依赖 W01–W04；宣称手机支持时，另外要求 W09–W11 的真实设备矩阵通过。手机未验收不阻止已验收的桌面增量交付，支持范围须明确。
- W06 保持原有组格式和呈现门槛；手机已支持时，新增组也要覆盖触摸与窄屏回归。

## 2. W08：按光标显示布局块边框高亮

### 行为约定

- 在插件设置中新增选项，中文名称保持用户指定的 **“保持布局块边框高亮”**，同时提供英文名称和说明。
- 默认开启，缺少该设置的旧用户继续保持现有常驻高亮。关闭后，普通布局边框与光晕只在编辑光标进入该块范围时显示，离开后隐藏；悬停不能独立触发这层高亮。
- 块范围包含开始／结束注释及中间源码行。非空选区按实际光标端 `head` 判断，多光标分别归属对应块；单纯选区覆盖某块不等于光标进入该块。
- 布局内部文字栏编辑器的输入光标也属于该布局块。切到另一窗格、笔记或结束文字编辑后，原块不能因保留的焦点状态继续高亮；自动恢复的非用户文首光标与现有源码展开规则一致处理。
- 高亮状态按窗格与运行期块身份维护。真块、浮动替身及保留的只读预览使用同一状态，不能在滚动交接时丢失或串到重复块。
- 当前主编辑器光标进入块会触发源码展开。须为展开后的实际块范围或保留预览提供对应提示，并通过原型确定呈现方式；不通过强留旧 widget 或改变源码展开规则实现高亮。
- 本选项控制普通边框高亮，错误提示和拖动落点反馈仍表达各自状态。隐藏高亮保持透明边框的原占位、内边距、命中区域和缩放手柄可用，不造成布局尺寸变化；阅读视图与 PDF 保持现有无编辑高亮的呈现。
- 设置切换即时作用于已打开的编辑窗格，保存后重载保留；只改插件设置，不改笔记。

### 验收

关闭／开启、鼠标与键盘进入／离开、源码展开、文字栏编辑／中文组字、非空选区／多光标、重复块、多窗格、切换笔记、真块／替身交接、插件重载均有定向证据。检查开关前后的布局尺寸和正文位置不变，hover 不破坏关闭常驻高亮的行为，设置缺失时兼容旧用户；类型检查、lint、相关逻辑测试和生产构建通过。

## 3. W09：手机平台与交互可行性验证

目标平台为 Android 和 iOS 的 Obsidian，逐一记录实际设备、系统／宿主版本和支持范围；平板作为后续扩展记录，不替代手机验收。

- 审计桌面专用依赖、窗口／文件接口、菜单／看图／附件路径，以及宿主 Worker、阅读高度、CodeMirror 和文字编辑接口在手机上的可用性。
- 只在专用测试库用候选构建验证安装、启停、打开／编辑／保存／重开、图片／视频和内部接口失效退路。候选安装所需 manifest 调整留在测试构建中，正式支持声明在 W10／W11 验收后修改。
- 实测手指滚动、点击、长按、拖动阈值、pointer cancel、软键盘与系统返回；确认哪些桌面操作需要可见按钮或菜单入口，覆盖无 hover、右键和物理键盘的场景。
- 按平台产出能力表、阻断项与可行交互原型。桌面窄窗和移动模拟只作辅助；缺少某平台真实设备证据时，该平台状态保留为待验收。

## 4. W10：手机显示、文字输入与生命周期适配

依赖 W09 能力结论，以及 W01 对同步／测量阻断问题的处理。

- 以手机实际 CSS 视口为基准覆盖竖屏、横屏和旋转；暂以 320／360／390／430px 作窄屏样例，结合设备的安全区和宿主面板宽度记录实际观测范围。
- 布局块、文字栏、分栏、图片／视频、公式和菜单在窄屏可读可操作；宽表格等确需横向滚动的内容在自己的容器内处理，不把整篇笔记撑出视口。不通过改写用户设置或原文获得临时窄屏布局。
- 点击文字进入编辑，验证软键盘弹出／收起、中文组字、选区、复制粘贴、撤销／重做和完成／取消入口；键盘遮挡时仍可操作，不误触主编辑器或提前提交未完成组字。
- 补齐阅读／编辑模式切换、慢资源、旋转、应用前后台、返回笔记、长浮动虚拟滚动的测量失效与清理。高亮选项在触摸输入下使用相同的光标语义。
- Android／iOS 分别记录笔记保存重开、原文守恒、可见区域、滚动与错误；不能用桌面截屏或模拟器尺寸说明完成手机验收。

## 5. W11：手机触摸操作接入统一规划

依赖 W10 和 W03／W04 的计划与事务契约。

- 整块移动、媒体重排、行高／列宽／块宽调整提供适合手指的命中区域；普通滚动不被拖动抢占。用 W09 原型冻结启动手势、移动阈值和触摸捕获规则。
- 没有右键、hover、双击或快捷键时，菜单、恢复默认、源码编辑和完成／取消仍有明确入口；不强制复制桌面手势。
- 手指与鼠标使用同一最终布局计划。覆盖快速松手、拖出视口、边缘自动滚动、pointer cancel、系统返回、前后台切换和多指干扰；取消后零写入，测量未完成松手不产生稍后的自动提交。
- 一次操作一步撤销，媒体嵌入原文保留，错误／不可写块不误写；真块和替身都能按同一块身份操作。现有桌面点击、滚动与拖动须回归。
- Android／iOS 的核心操作矩阵、输入与保存重开通过后，才决定正式移除 `isDesktopOnly` 并公开手机支持范围；部分能力受限时提供明确入口或限制说明，不以能安装代替能使用。
