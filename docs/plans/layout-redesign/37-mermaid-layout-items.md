# Mermaid 独立布局项

更新：2026-10-11。用户确认的范围是“像图片一样作为独立布局项，可并排和缩放”。本功能在 `codex/mermaid-layout` 独立开发，基线为 0.7.3 源码线的 `89b4b66`；不追加已发布的 0.7.3，也不并入移动候选。

## 使用与范围

- 选中完整的顶层 `mermaid` 代码围栏（可同时选中图片／视频行），执行“把选中的内容包成布局块”。新布局中的图表是独立项，复用列宽、行高、单项宽度、整体缩放、排序、跨块移动、图注和移出菜单。
- 图表交给 Obsidian 自带的 Markdown 渲染器绘制。读取 Mermaid SVG 的 viewBox 作为原始比例，按布局尺寸等比显示，不新增 Mermaid 依赖。原生处理器要求小写语言名，因此大写 `MERMAID` 只在渲染副本中改为小写，笔记源码保持原样。
- 代码围栏、缩进、注释和图表正文保持原样。尺寸和分排关系只写在开始注释；顺序不变时，包括合并／拆分行在内，只改开始注释。排序和移出搬运整个围栏，不编辑内部代码。
- 已有 V2 文字布局中的 Mermaid 仍是文字栏内容，不自动迁移。普通代码、引用／列表内的围栏、未闭合围栏不转成图表项。阅读视图按完整布局接管跨原生段落的项；PDF 导出等待图表异步渲染完成。

## 格式边界

本分支使用 `{"v":3,"kind":"media"}`，`rows[i].items` 表示第 i 行的项数。正文按源码顺序保存标准媒体嵌入和完整 Mermaid 围栏，项的连续排列与 `items` 共同决定行列。指定 `items` 时必须全部为正整数，且总数精确覆盖所有项；否则只显示、不写入。省略全部 `items` 时，沿用媒体物理行，加上每个完整图表各自的一行布局。

此格式只有一个布局块，不建立成员 ID、groupId 或跨块关系。它与 [W06 组格式候选](04-groups-and-format.md)不同：本解析路径只识别 `v:3` 且 `kind:"media"`，其他 V3 继续只读；两项组 ADR 仍为 proposed，组创建门槛保持不变。此开发格式尚未公开发布，后续组格式不能复用 `kind:"media"`。

把图表拖入普通 V2 图片布局时，仅把目标块显式升级为本格式；源与目标编辑必须一起成立、一起提交。未知自定义 `kind` 冲突或最终源码不能完整读回时，整次移动不写入。旧 0.7.3 不理解 V3，会保留源码并关闭布局写入；更早且缺少未知版本统一写入保护的构建不承诺安全降级。
