# 01 模型与多维研判

状态：规划。与 [领域词汇](../../../CONTEXT.md)、[当前设计](../../DESIGN.md) 配套阅读。

## 1. 必须区分的用户需求

| 用户意图 | 内容归属 | 推荐模型 | 不能混用的行为 |
| --- | --- | --- | --- |
| 同一行放几张媒体 | 同一个布局块 | 现有媒体行 | 不新增组来替代成熟的行模型 |
| 图和左右说明文字并列 | 同一个布局块 | 现有文字栏 | 不把栏内文字变成块外正文 |
| 两个独立文字／媒体块明确并列 | 内容仍分别归属成员块 | ParallelGroup | 不拼接正文或将两个块合成一个 V2 内容模型 |
| 左右浮动之间是普通正文 | 普通正文留在主编辑器 | WrapSet + FlowRegion | 不把正文塞入 Grid 的中间列或另开文字编辑器 |
| 将独立块移动到段落前后 | 内容跟随块 | BodyAnchor + placement intent | 不以当前屏幕像素作为持久化位置 |

ParallelGroup 首版只支持正常文档流中的单层并列，成员本身不向组外浮动。组整体浮动与组嵌套另行做原型；当前旧笔记的双侧浮动功能继续通过 WrapSet 支持，不依赖新组功能上线。

## 2. 不变量

| 编号 | 必须维持的性质 | 验证方式 |
| --- | --- | --- |
| I1 | 媒体嵌入、栏内文字与非目标原文不因布局操作被改写 | 逐段原文比对、CRLF／空白样例、笔记哈希 |
| I2 | 渲染、测量和创建运行期身份从不写笔记 | 写入入口审查、观察 Vault／编辑事务 |
| I3 | 一个手势的全部目标修改原子提交，任何写入目标或只读依赖的原文不匹配时全部取消 | 事务计数、只读依赖变化、过期锚点、交叠范围测试 |
| I4 | 候选落点与实际可实现落点明确区分；有效预览描述最终计划 | 预览矩形与松手后 DOM 测量对比 |
| I5 | 块身份不随上方插入文字改变，不由像素位置或当前高度决定 | 重复原文块、编辑前文、撤销／重做 |
| I6 | 相同内容和环境得到相同布局规则；各窗格自行测量 | 同宽／异宽双窗、样式变化 |
| I7 | 每窗格只有实际完成呈现才推进呈现版本 | 延迟加载、旧回调、双阅读窗格测试 |
| I8 | 无新输入时求解和测量结束，不持续产生补偿事务 | 稳定帧及 dispatch／重测计数 |
| I9 | 合法布局不发生对象重叠；正文剩余空间不足时有明确解法 | 同侧、异侧、宽度冲突、无正文 EOF |
| I10 | 旧格式含义在兼容层中解释，新功能只迁移操作明确涉及的块 | 老笔记打开无 diff、目标 opener 范围核对 |
| I11 | 最终写入源码经重新解析、关闭重开后仍可还原同一布局意图 | 序列化往返、插件重载、双视图及撤销／重做 |

I9 的正文宽度阈值须通过 P0a 校准为一种明确策略：正文允许自然下降到浮动以下，或将候选浮动下降到保留正文宽度的位置。两者不能由不同视图各自决定。默认候选为后者，作为新操作选取可写位置的约束。最终位置必须通过现有 V2 的源顺序、wrap、skip 表达，再由统一兼容规则读取；不能依靠“刚操作过”的内存标志改变重新打开时的呈现规则。只读打开既有 V2 不强制新增正文通道阈值、不写笔记。

## 3. 多维比较

以下高／中／低是工程判断，不是已经跑出的性能分数。

| 路线 | 多块规则完整性 | 正文原生编辑 | 双视图一致性潜力 | 格式／实现代价 | 判断 |
| --- | --- | --- | --- | --- | --- |
| 继续增加两块之间的补偿分支 | 低，排列增多后继续扩展 | 高 | 低，依赖宿主各自修正 | 初期低，维护成本上升 | 仅作为有限回归修复，不作为主架构 |
| 所有外部环绕改成 Grid | 对内部并列高，对跨段绕排不适用 | 需改变正文归属 | 组内高 | 中到高 | 不满足左右浮动夹普通正文的需求 |
| 全篇自由画布／绝对定位 | 可定义自由坐标 | 需要接管正文流与选择映射 | 需重建全部宿主适配 | 高 | 超出当前 Markdown 插件范围 |
| 明确关系 + 共享规划 + 两种宿主适配 | 高，但需测量实际约束 | 保留 | 高，仍需原型证明 | 分阶段中到高 | 推荐路线 |

共享规划的意义是同一份关系和约束规则，不是共享 DOM 或跨宽度复用同一套矩形。浮动定位、块高、正文重排之间存在依赖，纯函数核心须接收宿主的测量结果；浏览器仍负责实际文字排版。

## 4. 推荐的对象与职责

下面是模块契约草案，文件名可在 P1 实现时调整；不要求为了命名先建立空模块。

| 对象 | 内容 | 生命周期／边界 |
| --- | --- | --- |
| DocumentSnapshot | 精确源文本、文件实例、来源分支、快照 ID、递增版本、块与关系 | 不同源缓冲分开；撤销到旧文本也产生新的事件版本 |
| BlockRef | 运行期／持久身份、源范围、内容版本 | 身份和可写原文锚点分别保存 |
| BodyAnchor | 顶层正文边界的运行期引用与文本校验信息 | 映射编辑事务；不在普通正文里自动插入 ID |
| ParallelGroup | 明确成员顺序、列宽、间距、对齐 | 首版成员连续且单层，内容归属不变 |
| WrapSet | 相关浮动、锚点、对正文产生的约束 | 不等同于源码立即相邻的两块；包含仍影响范围的前置同侧浮动 |
| FlowRegion | 已知环绕影响范围与其结束证明 | 上界未知时标记未知，不能凭遇到一段普通正文就断言浮动结束 |
| DropIntent | 文档边界、浮动侧、相对偏移或组内插入槽 | 表达用户希望做什么，未包含成功承诺 |
| ResolvedLayoutPlan | 可读回的候选文档、有效落点、宿主需求、只读断言、编辑计划、测量状态 | 引用来源快照、发起窗格、环境、视口与手势序号，匹配才可提交 |
| ViewProjection | 当前窗格对快照的呈现和测量状态 | 窗格切换文件／关闭时失效 |

正文锚点和旧块的身份由事务位置映射、原文及邻近上下文匹配维护。不能用“恰好唯一原文”作为身份分配的唯一规则；重复块需保留当前实例的位置映射。原文唯一匹配仍可作为当前写入规则中的有限回退。

只读依赖与写入目标分开：邻块、组成员、间隔及目标边界可参与 `readSet` 校验，而不产生 BlockEdit。候选的实际源码必须可重新解析并得到同一意图；现有格式表达不了的候选不能标为 ready。身份无法在外部全文替换后无歧义映射时重建运行期实例并中止旧操作，不猜测两个重复块的历史身份。

## 5. 四个需要提前排除的错误假设

1. **显式组就能解决所有浮动**：组能统一内部并列高度，但不能让普通正文从一个实心浮动组的中间穿过。
2. **只要有 Block ID 就能直接写回**：ID 能辅助身份；实际文件、编辑器模式、目标原文及边界仍必须核对。
3. **文档 revision 一致就可共用高度**：宽度、字体、主题、媒体尺寸和文字编辑状态也影响高度。
4. **有限重试等于同步已完成**：等待宿主加载和真正完成绘制是不同状态，不能提前记录成功。

## 6. P0 的决策门槛

| 未知项 | 原型要回答的问题 | 不通过时调整 |
| --- | --- | --- |
| 旧 V2 候选排版 | 不写真实笔记，候选的最终源顺序／设置能否读回并匹配真实宿主？ | 调整测量方案或限制可表达落点；P3 不发布未证明的 ready |
| 正文锚点 | 空行、标题、列表、代码／公式结束、同侧大浮动如何确定受影响范围？ | 扩展边界模型及测量范围，避免局部两块推断 |
| 环绕约束 | 对源码排序和 `clear` 的限制能否得到最终合法位置？ | 定义可实现的吸附／下移规则，明确展示受影响对象 |
| 同步生命周期 | 有哪些可靠事件能唤醒延后加载的阅读视图？ | 采用保持 pending 的事件调度与受控重绘；不调用 setViewData 覆盖用户缓冲 |
| 新组格式 | 未知版本保护能否覆盖命令、批处理和模型编辑全部入口？ | 当前基线已有移除注释绕过；先补齐 R1 入口，再核定支持的降级版本 |
| 组内文字编辑 | 整组作为替换部件时，光标、中文组字和撤销能否保持？ | 先只读组呈现与源码编辑，交互门槛未通过不标为完整组功能 |

主路线在以上门槛下成立。门槛的作用是决定实现方式与交付范围，不是反复添加针对每种异常的防御分支。
